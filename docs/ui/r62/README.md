## M4 收款/退款幂等：三个落钱入口（request_id 无画面，证据为弹窗实拍 + 断言）

本轮 M4 给三个落钱入口（订单收款、打样费收款、预收退款）接了幂等键：桌面每次提交生成
`request_id` 随请求带上，**成功之后才换号**——失败重试沿用同一个 id，服务端同 id 重放
直接返回第一次的结果，不再落第二笔。幂等键本身没有任何画面（不弹提示、不加字段），
界面形态就是原来那三个落钱弹窗，实拍如下；行为由 e2e「R62/M4：收款/退款幂等」+
HTTP 冒烟「收款幂等」的断言锁着（同 id 重放只落一笔、重放返回第一次的结果、桌面三处
接线检查）。

拍法：`scripts/shot.sh`，数据目录先 `npm run seed`；退款弹窗要先有预收，
截图用 JS 通过 `window.api.orders.addPayment` 多付一笔制造预收后再点「退还」。

## 没有独立画面的行为

- **保存成功清稿**：清掉之后界面没有任何可见变化（下次打开就是干净表单）；
  行为由接线断言锁着——`clearDraft` 在 `orders.update` 成功之后、`onSaved()` 之前，报错路径不清。
- **改动即暂存**：写 localStorage 的动作没有画面；由接线断言「saveDraft 接在 form/charges 变化上」锁着。
- **幂等键本身**（M4）：不弹提示、不占界面；服务端行为由数据层断言（只落一笔、返回第一次的结果）锁着，
  证据为断言输出。
