## 二、金额口径核对（铁律第 2 条：动之前先 grep 消费方）

本轮**没有改任何计算公式**，动的是「单据存档金额从哪儿取」。我 grep 并核对过的消费方，全列在这里：

| 概念 | 唯一入口 | 本轮动没动 | 消费方（逐个核过） |

| 毛利 | `electron/services/money.ts` + dashboard | **没动** | 工作台「—」、报表黄条、订单详情毛利卡 |
| 合计（纸面） | 货值+费用，`renderPi/renderCi/renderQuotation` | **没动公式**；PL 模板修了个 `}` | PI / CI / 报价单预览（三张截图） |
| 存档金额 | **新增** `shared/documents.ts` 的 `orderDocAmount()` / `ciDocAmount()` | 动了（从 OrderDetail 里两处重复表达式收成一个函数） | 订单详情 PI / PL 存档、CI 存档、存档表、操作历史事件文字 |

以前 PI/PL 存档金额是渲染层各写各的 `order.grandTotal ?? order.totalAmount`，现在收成 `orderDocAmount()` 一个函数，**并写成断言锁死**：e2e 里 `PI / PL 存档金额 = 含费用合计`、`CI 存档金额（默认费用行）= 含费用合计`。以后谁改口径，测试先红。

新增的 7 条断言（`scripts/e2e-test.ts`，全部 ✓）：

1. 报价单合计口径 = 订单含费用合计（同一个 money.ts 入口）
2. 报价单纸上印的合计 = PI 纸上的合计
3. PL 纸面不印金额（数量单据，金额看存档行）
4. **PL 纸面没有多余的 }（模板结尾闭合正确）** ← 本轮抓的 bug
5. PI / PL 存档金额 = 含费用合计（`orderDocAmount`）
6. CI 存档金额（默认费用行）= 含费用合计（`ciDocAmount`）
7. CI 调过费用行后，纸上印新合计（差异理由印在费用行里）
