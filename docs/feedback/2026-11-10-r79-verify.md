## 二、逐项亲验记录

### ① 纯函数复核——SQL 文本与参数逐字一致，mysql.ts 只管执行

重构前（2957b41^）与重构后（HEAD）的 mysql.ts 逐字 diff：

- **upsert**：旧内联的 `set` 三元（increment → `${valueCol} = ${valueCol} + ?`；
  overwrite → `${valueCol} = VALUES(${valueCol})`）、params 三元（increment 三参
  [key, value, value]、overwrite 两参 [key, value]）、SQL 模板
  `INSERT INTO ${table}(${keyCol}, ${valueCol}) VALUES(?, ?) ON DUPLICATE KEY UPDATE ${set}`
  ——与 buildUpsert 里的产出**逐字符相同**，只是搬进了 mysql-sql.ts；mysql.ts 现在是
  `const { sql, params } = buildUpsert(spec); await this.conn().query(sql, params)`。
- **insertIgnore**：旧模板 `INSERT IGNORE INTO ${table}(${cols.join(', ')})
  VALUES(${cols.map(() => '?').join(', ')})` 与 buildInsertIgnore 逐字符相同；
  mysql.ts 只剩 `query(sql, params)`。
- 语义对照注释（与 SQLite ON CONFLICT DO UPDATE / INSERT OR IGNORE 同一套）没丢，
  升级成 mysql-sql.ts 头部的语义对照 docblock。「组装不在 MysqlDb 里」成立。

### ② 六条本地锁——实跑全绿，且真不需要 MySQL 实例

server/test/db.ts:98-113（源注释标 R79），实跑日志六条全 ✓：

1. ✓ upsert overwrite 的 SQL（ON DUPLICATE KEY UPDATE = VALUES）——整句字符串精确断言；
2. ✓ upsert overwrite 的参数（两占位符）——[key, value] 逐值断言；
3. ✓ upsert increment 的 SQL（旧值 + 新值）——整句精确断言；
4. ✓ upsert increment 的参数（三占位符，旧值+新值各填一次）——params[1]===5 && params[2]===5；
5. ✓ insertIgnore 的 SQL（占位符与列数一致）——`VALUES(?, ?)` 与两列对应；
6. ✓ bizMonthExpr 报错不静默（消息指向先用 SQLite）。

第 6 条「构造即测」我专门核了：MysqlDb 构造器只 `mysql.createPool({...})`——mysql2 的
池是惰性的，**构造不发起连接**；bizMonthExpr 第一行就 throw（「业务月函数还没有 MySQL
实现……请先用 SQLite 文件」），不碰 `this.pool`/`conn()`。所以 `new MysqlDb({host:'db.local',...})
.bizMonthExpr('created_at')` 在无网环境同步 throw、消息含「还没有 MySQL 实现」——
断言条件 `bizThrew !== null && includes('还没有 MySQL 实现')` 精确命中。R66 立的
「要么真实现要么报错不静默」从此有测试锁：将来谁把 throw 删了换成静默实现或吞错，
套件当场红。

## 三、疑点 / 观察项（极小）

1. 六条锁挂在既有 section 里（没有独立的「R79」section 标题），grep 断言名都能命中、
   源注释带 R79（db.ts:98）——可发现性够用，提一句备查。
2. 锁 6 在 TS 里用 `require('../src/db/mysql').MysqlDb` 动态取类——编译后 CJS 环境成立
   （typecheck/套件双绿），写法与文件内其余 import 风格略异，无碍。
3. SQL 精确断言是「锁现状」式测试：将来有意改 SQL 方言（比如换参数占位风格）要先改
   断言——这正是锁的本意（改方言必须过人眼），不算缺点。
