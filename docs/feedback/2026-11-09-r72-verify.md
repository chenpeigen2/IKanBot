## 二、逐项亲验记录（重构轮看形态）

### ① 钩子改形——签名、取数来源、兜底分支三处都对了

- writeBackup（164-168 行）：`const dbEntry = entries.find((e) => e.name === 'ikanbot.db')` →
  `hooks.migrationReportFromSnapshot(dbEntry.data)`——**对账喂的就是包里那份 ikanbot.db 的字节**，

### ② 两处实现——同一形态、同一算法，没有第二份

- **桌面**（`electron/services/backup.ts:181` `migrationReportFromSnapshotDb`）：字节写临时文件 →
  `new RawDatabase(tmp)`（node-sqlite3-wasm 裸驱动，绕开 electron/db 的锁目录包装）→ 套异步 Db
  适配（get/all 转异步、run 给空桩——migrationReport 只读，run 不参与）→ 喂给 core 的
  `migrationReport`；`finally` 里 raw.close + rmSync 临时文件，两层清理都在。
- **服务器**（`backup.service.ts:120`）：同形态——临时文件 + `new Database(tmp)`（同一
  node-sqlite3-wasm）+ 同样的异步适配 + 同一个 core `migrationReport`，注释把动机写明
  （「主连接算与包内快照之间有写间隙，diff 会假警报」）。
- **全仓库 grep `migrationReport`**：引用面只有 `core/migration.ts`（算法本体）、`core/backup.ts`
  （钩子定义与调用）、两处壳层（钩子实现 + 恢复后现算的 after）、`scripts/e2e-test.ts`（测试）——
  **对账指纹 SQL（COALESCE(SUM(amount)…) 等）只在 core/migration.ts 一处**，没有第二份算法。
  money.ts 里的 SUM 是预收派生域自己的查询（不同用途），不算。
