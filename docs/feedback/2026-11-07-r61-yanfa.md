### ② EACCES 人话 —— 已做并验过（TDD 先红后绿）

复验报告里 chmod 000 存档目录 → 500「服务器内部错误」五个字裸奔。`AllExceptionsFilter` 补上文件系统错误映射：
EACCES/EPERM（权限）→ 说清是哪个路径、指到「找管服务器的人」；ENOSPC（磁盘满）、ENOENT、EROFS 同样各有各的话；原始错误仍进服务端日志。

- 红阶段真实复现了复验报告那句 500（`server/test/e2e.ts` chmod 实验）；绿阶段同时锁住「权限失败那次不留半条版本记录」（R57 老规矩）。
- HTTP 冒烟 188 → **202**（+14：备份节 12 条 + 权限话术 2 条）。

### ③ 401 清假登录态 —— 已做并验过（TDD 先红后绿）

后端换秘钥后设置页还挂着「已登录：某某」——本地存的用户名不是服务端验过的。现在任何远端**业务**请求收到 401：

- 主进程清掉 safeStorage 里的登录态（`clearStoredAuth`），广播 `auth:expired`；
- 设置页订阅后刷新登录卡（变回未登录表单）并弹「登录已失效，请重新登录」（连续多个请求只弹一次）；
- 话术统一为「登录已失效，请到「设置 · 数据来源」重新登录」；登录接口自己的 401（密码不对）不受影响，仍回「用户名或密码不对」；
- 401 后重新登录马上恢复，不会被永久卡死（双模式测试有断言）。

双模式测试新增 6 条（401 节）：auth 文件被删、mode:get 回未登录、通知到达渲染层桥、重登恢复。老的「请先登录」话术断言同步升级为「登录已失效」（有意的行为变更，非口径漂移）。

### ④ token 过期不丢草稿 —— 已做并验过（TDD）

远端模式录单到一半 token 过期（或程序重启），新建订单表单不再丢内容。方案（选了「自动续」这条更省心的路）：

- 新模块 `src/shared/drafts.ts`：每次改动即暂存 localStorage（带暂存时刻；半截 JSON、字段残缺当场拒收并清掉，绝不拿坏稿填半个表单）；
- 重新打开表单自动回填 + toast「已恢复上次没保存的草稿（几点几分暂存），保存成功后自动清掉」；
- **建单成功才清稿**：401 拦下、取消、报错都留着——重新登录后重开表单就续上；
- 没动过笔不存稿（自动带出的默认值不算动笔），不会平白多出「空草稿」骗人恢复提示；
- 范围：新建订单弹窗（录单主场景）。编辑已有订单的弹窗没做——那些字段本来就已在库里，弹窗开着时内容也不丢；
- e2e 新增 11 条：暂存逻辑 7 条（roundtrip/覆盖/清稿/坏稿拒收）+ 接线检查 4 条（改动即存/打开即恢复/成功才清/清只在成功分支）。

实拍：`docs/ui/r61/order-new-draft.png`——客户、币种、汇率、港口、PO 号、备注全部回填 + 恢复 toast。

### ⑤ docs:reveal 整目录远端浏览 —— 正式决策「不做」，已做清理

决策依据：存档列表每一版都有「打开 / 所在文件夹」，远端模式也能用（拉到本机临时目录再显示）；整目录浏览唯一多出来的价值是「看见服务器 docs 目录长什么样」，为这个再做远端列目录界面不值当。而渲染层从来只传单版路径，无参分支（本地开根目录/远端报「后端机器」）是半死代码。

清理：`docs:reveal` 签名收紧为必填 `filePath`（api.ts / preload / ipc 三层同步），无参分支删掉；mode-test 断言更新；决策写进记账。

## 二、大件：备份簇搬后端 —— 已做并验过

以 `electron/ipc/index.ts` 实际通道为准，先列清单：backup:create / list / pick / inspect / restore / reveal / lastResult 共 7 条。

| 通道 | 远端模式现在怎么走 |
| --- | --- |
| backup:create | **服务器侧打包**（服务器的库 + 图片目录 + 单据存档目录整包，VACUUM INTO 一致快照），本机只转发 |
| backup:list | 服务器备份目录列表（新→旧，带时间与体积） |
| backup:inspect | 服务器侧开包看摘要（订单/收款数、文件数、体积） |
| backup:restore | 服务器整库导入 + 文件目录替换 + 失败全路回滚；**服务器不重启进程**（SqliteDb 新增 reopen，恢复后重接库文件） |
| backup:pick / reveal / lastResult | 本机侧：对话框挑本机 zip、开本机目录（远端给人话「备份在服务器上，直接在列表里选」）；lastResult 跟着备份发生地走（远端读服务器 settings） |

### 判据收进 core（单一真源）

`core/backup.ts`（桌面与服务器同一份）：排队一次一包、同秒撞名 -2/-3、先写 .part 验货再改名、快照降级留痕、按天去重、恢复前压 pre-restore 反悔药、附件目录先换后换库 + 失败全路退回、路径守卫。`core/zip.ts` 一并收编（旧 import 路径转发，e2e 不用改）。桌面门面只接本机快照（VACUUM INTO）、原生选择框与 relaunch。

### 服务端

- `/api/backup/create|list|inspect|restore` 四条路由（鉴权同其他域）；
- **定时器在服务器**：启动 10 秒后补查当天备过没有、每小时喊一次——「每天启动一备 + 每小时补查」的口径由服务器兑现；桌面远端模式的 autoBackupOnStart 不跑（main 进程判模式），设置页文案说清；
- **恢复期间的写闸门**：恢复在途时，除 backup: 自家通道外的业务 POST 一律 503「恢复期间请全员停手：服务器正在用备份恢复数据……」——多用户风险第一版先把话说清，完整并发方案留 M4/M5；
- MySQL 侧备份/恢复给人话拒绝（要走 mysqldump，M5 落地），SQLite 全功能。

### 测试（先红后绿，测试与实现同提交）

- **HTTP 冒烟 188 → 202（+14）**：备份节 12 条——无 token 401、服务器打包落备份目录、列表带体积、inspect 摘要、目录外路径拒收、非 .zip 拒收、恢复对拍（造账→恢复→张数回到备份那一刻）、写闸门（恢复期间业务请求 503、备份页照常用、恢复完放开）+ EACCES 话术 2 条；
- **双模式 128 → 140（+12）**：401 节 6 条 + 备份节 6 条——远端备份落在服务器备份目录、列表读服务器那份、inspect 摘要、lastResult 读服务器设置、恢复对拍（张数一致、新账被旧包盖掉、查无此人）；
- **桌面 e2e 2302 → 2313（+11）**：小修④草稿；
- **R36/R43 不退化**：桌面备份的排队、pre-restore、恢复写闸门（「恢复通道自己在闸门里」「不让第二次恢复插队」）等断言原样保留、全绿——core 抽取后桌面行为一字未变。

### 过程中被测试抓出来的真问题（都修了）

1. 服务器备份目录不存在时第一次打包 ENOENT → core 里补「目录不存在就现建」；
2. 服务器侧 restore 后 `restoring` 旗子沿用桌面语义会永远举着（桌面靠进程重启放下）→ hooks 增加 `keepRestoringAfterRestore`：桌面举到死，服务器恢复完成当场放下；
3. SqliteDb 双重 close 抛「Database already closed」且 async close 的拒绝会逃出 try/catch → `isOpen` 守卫 + reopen 容错。

## 请文娟复验的重点

1. **远端模式备份**（如果你试后端模式）：设置页 → 数据备份卡，「立即备份」打的是服务器那份；下面的备份列表点「查看」先看摘要再替换；恢复期间服务器会挡住别人的录单（提示「请全员停手」），恢复完大家再继续。
2. **本机模式备份**：应该完全没变——路径、按钮、节奏都和以前一样；如果你发现哪里变了，那是我的 bug。
3. **录单不丢稿**：新建订单填到一半，把程序关掉再打开（或者后端 token 过期后重登再开表单）——上次的字应该还在，右上角会告诉你那是几点存的稿。
4. **后端换秘钥的假登录**：下次服务器换了秘钥，设置页的「已登录：某某」应该当场变回登录框，不再挂着假象。
