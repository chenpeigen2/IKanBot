## 三、本轮新发现（不是打回，是要记账）

1. **sweep 基线的 `/orders/13` 行不可复现（工具账，下轮必须收）**。`npm run seed` 只 `DELETE FROM orders`，**不重置 `sqlite_sequence`**——seed 出来的第一张单 id 取决于这台库历史上用过多少号：我 seed 出来是 **17~20**，研发重钉基线那天是 13。结果 sweep 扫 `/orders/13` 时单不存在，页面回落订单列表并弹「订单不存在」，探针读到列表大表格 **1486.648/504.648**，与基线的 982/0 必然对不上。「seed 后固定是 13」只在研发自己那台库上成立。修法很便宜：seed 里重置计数器，或者 sweep.sh 动态取第一张单的 id，别把 id 钉死在文档里。
2. **表格宽度对窗口落位敏感，「逐字节一致」有前提（工具账）**。同一台机器第一跑 `/products`、`/customers` 扫出 **1198**，第二跑 **982**（基线 982）——我的屏幕接了两台显示器，窗口落在哪块屏上尺寸不一样。基线要可复现，sweep 得把窗口尺寸钉死（shot 的探针同理），不然换屏/换缩放就是假漂移。
3. 两条都是**研发工具的账，不是产品 bug**：版面本身没有任何一处真溢出、真截断（8/9 行基线复现一致）。
