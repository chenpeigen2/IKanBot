## 二、逐项亲验记录

### ① 闸门不豁免——真的同一条闸，无后门

`electron/services/backup.ts` 是门面（`createBackup = core.createBackup`），判据真身在
`core/backup.ts` writeBackup（143-235 行）。note 在整个闸门里**只进文件名**
（154 行：`ikanbot-${stamp}${note ? `-${note}` : ''}.zip`），其余每一步对 note 无任何分支：

- 搬迁对账进包（164-175 行）：无条件从快照字节算，算不出也照打不豁免；
- verifyZip 读回（179-180 行）+ `inspectRestoredDb` 探针自验（185-186 行）：无条件，
  验不过按失败计、坏包不落盘；
- markOk / markFail / 降级留痕（212-233 行）：无条件，同一条记账路。

全仓 grep `'export'` 字面量：**唯一一处**就是设置页按钮
（`src/renderer/src/pages/Settings.tsx:866` 的 `backup.create('export')`）——core、electron、
server 侧没有任何 `if note === 'export'` 之类的旁路。「同一条闸门」这句我认。

### ② note 三层透传——走读接线齐，但没行为级断言（见第三节第 2 条）

- preload（`electron/preload/index.ts:216`）：`create: (note?) => call('backup:create', note)`；
- ipc（`electron/ipc/index.ts:523`）：远端 `remoteCall('backup:create', [note])`、
  本机 `createBackup(note || 'manual')`；
- 路由表（`electron/remote/client.ts`）：`args: ['note']` → HTTP body `{ note }`；
- server（controller → service）：`body.note` trim 后 `createBackup(note || 'manual')`。

旁证不串台：「立即备份」`create()` 不带 note → 照旧 `-manual`；自动备份是 core 内部
`createBackup('auto')`（304-326 行），不受本次改形影响。远端参数守卫（R56 的
「多传参数报错」）与 `args: ['note']` 对得上，不会静默丢。

### ③ R74 接线 grep 实况——声称四条，实为三条

e2e「R74：导出整库（搬迁用）」段（scripts/e2e-test.ts:4182-4191）实跑三条全绿：

1. ✓ 设置页有导出整库入口（搬迁用）
2. ✓ 导出整库打的是 -export 包（源码含 `backup.create('export')`）
3. ✓ 导出包仍走同一条备份闸门（backup.ts 含 createBackup）

声称的第四条「手册存在」**没有**——`grep migration.md / 手册 scripts/e2e-test.ts`
零命中。提交信息与 docs/ui/r74/README.md 都写「四条」，是虚报。顺带：第 3 条只是
grep 门面文件含 `createBackup` 字样，就算真写了豁免后门它也绿——锁不住实质，这轮
实质是我手工读 core/backup.ts 补验的（①）。

### ④ 手册可读性——四步能照着走，但两处我会当场问

`docs/migration.md` 四步结构清楚：导出（含对账进包）→ 带包（手动/远端自动上传）→
恢复（pre-restore 反悔药 / 停写）→ 对账核对（绿行/红块/老包明说）+ 回滚。核对点、
v0.5.12 分界都写了，大框架能照着走。但：

**问一（版本守卫，前提节那句会带偏人）**：手册写「反过来会被版本守卫拦下，提示
『这份数据的新版结构是 vX，当前程序只认到 vY』——**先升级老程序再导出**」。我把代码
原文对了出来（electron/db/index.ts:216-221）：被拦的场景是**包比新机器的程序新**
（老机器已是升级版），代码原话是「**请先升级程序再打开**」——升的是被拦那一头
（新机器）。按手册去「升级老程序再导出」：老机器程序本来就是新的，升完再导出包还是
v25，新机器照样拦，死循环。方向写反了。另外通篇 vX/vY 占位，没点明当前就是 v25
（schema.ts:673，MIGRATIONS 最大 25），用户拿提示里的数字对不上手册。

**问二（回滚一节薄，最大的坑没提）**：回滚只有 pre-restore 三行。手册从「导出」到
「恢复成功」之间的窗口里，**老机器能不能继续录单/收款**一句没提——这段窗口录的东西
不在包里，搬完就丢；搬完后老机器怎么处置（停用？卸载？两边同时录单会不会分叉）也没说。
第 4 步只管住了「红块别用新库录单」，没管住「导出后别在老机器录单」。做外贸的按这套
手册操作，最容易栽的就是这里。

（另有一条衔接疑点，不算手册本身：toast 与确认框都指路「docs/migration.md」——
electron-builder.yml 的 files 只有 `out/**/* + package.json`，docs/ 不进安装包，
**装好的应用里用户找不到这份手册**。仓库里写得再好，终端用户看不见。）

## 四、没验的（原因）

1. **真实远端服务器上的端到端导出**（远端模式点按钮 → 服务器落 -export 包）：
   无服务器环境；透传正确性以三层源码走读 + HTTP 参数映射机制（R56 守卫）为准，
   无行为级断言是我打回的理由之一，不是我替它背书的理由。
2. **sweep 九路由基线**：无重跑手段，信任提交信息「基线一致」；备份卡实拍覆盖画面层。
3. **红态**（对账算不出、探针自验失败）：本来就无 note 分支（①），红态路径与
   'manual' 完全同一份，R73/R70 的既有断言覆盖，不重复造。

## 复验结论

代码本身是好的：四套数字精确对上，闸门对 'export' 无任何豁免，三层透传接线齐，
按钮文案与确认框分得清，README/记账/截图索引都在。但这一轮的交付有一半是**手册**，
手册前提里版本守卫那句补救方向是反的（照做死循环）、回滚一节没管住「导出后老机器
别再录单」这个最容易栽的坑；再叠加研发报告整个缺失、声称的「四条接线」与「HTTP/双
模式覆盖 note」两处虚报——报告纪律这轮没守住，手册这轮也没到能发给业务员的程度。
返工三件事：补研发报告入库；接线 grep 补第四条（顺手给 -export 包名补一条行为级
断言）；手册改版本守卫那句、回滚一节补双机并行窗口的提醒。修完复验再谈发版。
