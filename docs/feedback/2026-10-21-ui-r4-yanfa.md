## 一、① 统计卡上色统一（S1 + P3）

### 问题
同一个"已收到的钱"，在订单详情是绿的、在报表是黑的；全站 `.stat` 有 4 个颜色变体，每个页面各挑各的。

### 做了什么
| 位置 | 改前 | 改后 |
|---|---|---|
| `styles.css:503` | `.stat.accent` / `.stat.green` / `.stat.amber` / `.stat.red` 四个变体 | **删掉 `.stat.green` 和 `.stat.red`**，只留 `.stat.accent`（蓝）和 `.stat.amber`（橙） |
| `OrderDetail.tsx:273,281` | 订单金额=蓝、已收/待收=绿 | 4 张卡**全黑** |
| `Reports.tsx:65,70` | 累计销售额=蓝、累计毛利=绿 | 4 张卡**全黑** |
| `Dashboard.tsx:73` | 待出货订单=蓝 | **去色**（订单数不是钱，不需要强调） |
| `Dashboard.tsx:67` | 待收款金额=橙 | **保留橙**（本屏唯一的"要动手"的卡） |
| `Customers.tsx:352,361` | 累计毛利=绿、未收金额=红 | 累计毛利**去色**、未收金额**改橙**（和工作台待收款同色） |

**定下来的规则**（写进了 `styles.css` 注释）：
> 统计卡默认全黑；一屏最多 1 张卡上色；同一种语义跨页必须同色。
> 橙 = 「钱还没到手」（工作台待收款金额 / 客户未收金额），蓝 = 强调色。

### 怎么验的

| `r4-dash.png` | 待出货订单 | `#1C2333` | ✅ 黑（去色成功） |

## 二、② 收款 / 出货两套状态色分离（S2）

### 问题
`ui.tsx` 两张映射表共用一套 5 个色板：`green` 同时给 `paid / settled / cleared / delivered` 四个状态 —— 一屏里"已收款"（钱）和"已签收"（货）是同一个绿。

### 做了什么
- `ui.tsx` 的 `SHIP_TAG` 六个值**全部改成 `'grey'`**（中性底灰）。
- `PAY_TAG` **一个字没动**（收款维度保持原配色）。
- **补了出口**：出货进度全灰以后，"做完了"不能只靠颜色认。新增 `SHIP_DONE` 标记 —— `已清关` / `已签收` 两档前面加一个 `✓`（形状标记，黑白打印和色弱也分得出）。
- 订单列表的**出货状态整列**现在都是灰底黑字；`r4-orders.png` 一屏底色从 4 种降到 **3 种**（灰/琥珀/蓝 + 收款列的绿），**绿色只出现在「收款状态」列**。
- 状态推进区（订单详情右侧）也走同一个 `ShipTag`，所以那儿的"备货中"也变灰了 —— 同一套规则，没有分叉。

**同时把新开的两个列表页也对齐了**（不然这轮改完、下轮又要在新页面重犯）：
- 报价单「状态」列 = 中性灰（旁边「结果」列才是彩色：待回=琥珀 / 成交=绿 / 没成交=灰），「已转订单」加 ✓；只有「已失效」用红（这一屏没有别的红色，不冲突）。
- 打样单「状态」列 = 中性灰（旁边「打样费收款」列才是彩色：未收=琥珀 / 已收=绿 / 下单抵扣=蓝）。

> 一开始我给打样单状态用了蓝色，截图一看同一行里「已寄出」和「下单抵扣」都是蓝的 —— 又变成"一个颜色说两件事"，所以退回灰。**这个改法是我看图看出来的，不是一次想对的。**

## 四、④ 表单 label 全中文（S4）+ 设置页栅格 / 截断（S6）

### 4.1 label 中文化
| 位置 | 改前 | 改后 |
|---|---|---|
| `Products.tsx:269` | `款号 Style No. *` | `款号 *` |
| `Products.tsx:277` | `品名 Description` | `品名` |

| `Customers.tsx:222` | `收件人 Attn` | `收件人`（顺手一起改了，全站不留双语 label） |

规则写进注释：**应用内表单 label 一律中文；中英双语只出现在 PI / PL / CI / 报价单这 4 种要发给客户的纸上。**

`r4-modal-product.png` 实测：12 个 label 全部中文，栅格左右对齐。
> 查了一下全站还剩的 label（`PI 号`、`汇率（1 USD = ? CNY）`、`客户 PO 号`、`单件净重（kg）` 等）—— 这些是**缩写/单位**不是双语对照，保留没动。

### 4.2 银行地址不再被切
`Settings.tsx` 收款账户卡：「银行地址」`w-md`（320px）→ **`w-lg`（520px）**，和「银行名称」同宽。

`r4-settings.png` 实测：原来在 "Guangdo|China" 中间硬切，现在完整显示 `No. 136 Huan Shi Dong Road, Guangzhou, Guangdong, China`，**尾巴没丢**。

### 4.3 同排控件宽度统一
`styles.css` 加：
```css
.field-row > .field,
.field-row-3 > .field { min-width: 0; }
```
**原因**：`field-row-3` 是 `repeat(3, 1fr)`，但栅格项默认 `min-width: auto`，`select` 的固有宽度会把那一列撑开（原来基准币种 393px > PI 有效期 360px）。加 `min-width: 0` 后三列等宽。

`r4-settings-defaults.png` 实测：**PI 有效期 / 默认定金比例 / 基准币种 三个控件现在都是 ~367px，完全一致**（原来 360 / 358 / 393）。

## 五、⑤ 状态列只读化 + 下拉框宽度（S5）

### 问题
3 个列表页 4 个状态列，2 个下拉、2 个只读 tag；而且只读 tag 高 20px、下拉高 22px，同一行差 2px，用户看不出哪个能点。

### 做了什么
| 位置 | 改前 | 改后 |
|---|---|---|
| `Quotations.tsx:171` | `<select className="sm">` 状态下拉 | 只读 `QuotationStatusTag` |
| `Samples.tsx:229` | `<select className="sm">` 状态下拉 | 只读 `SampleStatusTag` |
| `styles.css` `select.sm` | `min-width: 72px`（箭头贴字） | `min-width: 80px` |

**堵住的口子必须留出口 —— 出口都在**：
- 报价单：点这一行 → 打开报价单详情弹窗 → 里面**还是下拉框**（`r4-modal-quo.png` 实测，「状态」那行是下拉框，能改）。
- 打样单：点「⋯」菜单 → 「编辑」→ 弹窗里**还是下拉框**（`r4-modal-sample.png` 实测，「状态」下拉显示「已寄出」）。
- 两个只读 tag 都加了 `title` 提示，告诉用户去哪改。

**顺带清掉的**：`Quotations.tsx` 里那个只服务于列表下拉的 `setMeta` 函数（改状态走详情弹窗的 `setStatus`），删了；`Samples.tsx` 里那个只服务于列表下拉的 `saveFull` 函数，删了。`typecheck` 零错。

**关于业务取舍**：这一条审查报告写了"要周文娟点头"。我的判断是——**改状态的入口一个没少，只是从列表挪到了详情/编辑弹窗**，而且我在两个 tag 上都写了"去哪改"的提示。如果你更习惯在列表里直接改，跟我说一声，我把下拉框加回来并配一个统一的"行内编辑"标记（审查报告里也提了这个备选方案）。
