# R84 研发报告 —— 数据自检红框人话化 + toast 话术对齐（R83 复验挂账三条清偿）

日期：2026-11-14。基线 v0.5.25。每条标「已做并验过 / 已做但没验 / 没做（原因）」。

## 一、做了什么（R83 复验挂账三条 + 两条顺手）

1. **红框人话问题清单**（已做并验过）：core `dataHealthCheck` 新增 `problems[]`——三道闸
   各给「怎么办」：
   - quick_check 不过 → 「数据库文件自检没通过（库可能损坏）——请先不要录单，立即联系技术支持。」
   - 版本超前 → 「这份数据来自更新的程序版本（数据格式 vN，当前只认到 vM）——请先不要录单，
     把程序升级到最新版再打开。」
   - 表 COUNT 抛错（R83 版里这路会把整次自检炸成未捕获异常）→ 逐表 catch：「核心表 t 读
     不出来（数据结构异常）——请先不要录单，立即联系技术支持。」
2. **ok 判定恒真式清偿**（已做并验过）：`ok` 从 `(tables['orders'] ?? 0) >= 0`（复验指出的
   恒真注脚——实际兜底靠 COUNT 抛错，语义等价但字面误导）改为 `problems.length === 0`。
3. **红框渲染 problems + 原文技术行**（已做并验过，实拍 docs/ui/r84/）：红框里 problems
   逐条人话先行；quickCheck 英文原文单独一行「自检原文（给技术支持看）：…」照给——R83
   复验认可原文可见（当时把「quick_check 错误原文 + v25 + 12 表行数」当优点记录），截图
   发技术支持就够排查。绿框维持原 hint 行不变。
4. **catch toast 话术对齐**（已做并验过——源码断言锁，UI 态不可复现见第四节）：「数据自检
   没跑出来：X」→「数据自检没跑出来：X——请先不要录单，立即联系技术支持。」与红框同话术。
5. **顺手两件**（已做并验过）：版本话术原半成品写死「升级到 v0.5.25 或更高」→ 改「升级到
   最新版」（发版即过时的话术不留）；e2e 裸库喂法从 require 别名 + 每次调用重开不关 → 改
   顶部既有 Database import + 用完即关。

  COUNT 抛错还被逐表接住。toast 只在 health 通道整体跑不起来（远端错误/磁盘错）时出现。
