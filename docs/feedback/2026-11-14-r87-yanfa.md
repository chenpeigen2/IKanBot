# R87 研发报告 —— HTTP 冒烟改单簇实弹（108/108 全覆盖）+ 深度损坏无指引直锁

日期：2026-11-14。基线 v0.5.28。每条标「已做并验过 / 已做但没验 / 没做（原因）」。
本轮**桌面与 core 零代码改动**（e2e 只加断言）——变的是 server 测试、审计工具与文档。

## 一、做了什么

1. **路由功能覆盖审计工具入库**（已做并验过）：`scripts/audit-http-coverage.cjs`
   （`npm run audit:http`）——server 控制器 108 条路由逐条与 HTTP 冒烟正文对表。
   两个口径坑在工具里修掉并写明：一个 controller 文件可挂多个 @Controller 块
   （dashboard.controller.ts 同时挂 api/dashboard、api/report、api/export——首版脚本只取
   第一个块，把 /api/export/csv 误记成 /api/dashboard/csv）；参数路由（files/images/:name）
   按参数段前缀匹配。修完后实测：**12 条路由零功能断言**（修前初版误报 16 条）。
2. **12 条路由补 15 条功能锁**（已做并验过）：改单簇 orders updateItem / removeItem /
   replaceItems / setParties / lastTerms（行数款式经 orders/get 复核、币种汇率经
   confirmed 单继承）；pl addLine / deleteLine；products setActive 上下架 0→1；打样三层
   deletePayment（拒空原因）→ 取消（拒空原因、原因入备注档）→ delete；files 图片 GET
   锁成「**故意不挂鉴权的唯一例外**」（R59 记账：`<img>` 带不了 Authorization 头，挂了
   远端商品卡全白——现在谁「补齐鉴权」这条当场红）；docs listQuotation 空数组形状。
   审计终态 **108/108**。
3. **顺手实证的护栏**（已做并验过）：装箱守恒闸经 HTTP 照样拦超装（「订单 2 件，其他箱
   已装 2 件，还能装 0 件」——测试造数据时当场吃到，修数据后过）；打样删单的两道闸
   （取消要原因、删单前应收归零）全实弹。
4. **桌面 e2e +1（R86 复验小账清偿）**（已做并验过）：深度损坏（freelist 坏 + 缺 10 张
   核心表）→ problems 只报「核心表读不出来」family + 首条，**不混**「立即备份」指引——
   指引条的作用域从此有直锁（R86 复验用一次性脚本实证过行为，本轮把锁补进套件）。

## 二、红验证

本轮为覆盖锁（被锁行为已在桌面 e2e core 层锁死，HTTP 层是接线与合同的锁），无法先红
后绿。红能力当场实证两回，非转述：① 测试自身键名错两处（lastTerms 收 `customerId` 不是
`id`、setParties 收 `id` 不是 `orderId`——桌面走位置参数数组、HTTP 走命名键，合同面
不一致当场 ✗）→ 修正后绿；② 装箱守恒闸对超装数据当场 400 拒（「还能装 0 件」）——
护栏经 HTTP 真在干活。
