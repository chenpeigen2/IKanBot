## 一、做了什么

1. **远端健康链路三连拍**（已做并验过，docs/ui/r94/）：真起后端编译产物（freelist 坏副本
   库 + bootstrap wenjuan），curl 实弹先核 `/api/settings/health`（ok:false + problems[0]
   人话「数据库文件自检没通过（库可能损坏）——请先不要录单…」），桌面远端模式注入真登录
   （`window.api.mode.login`）后：
   - **工作台红条**：查的是服务器那份坏库——problems[0] 经 HTTP 通道；统计/待办照常
     （freelist 级损坏 COUNT 全活）；
   - **锚点直滚**：`#/settings?scroll=backup` 直滚生效——HTTP 慢通道下 R92 的 [s, source]
     闸等到数据到位才滚（竞态修复的远端真实验证：数据到位才滚与传输耗时无关）；
   - **红框详情同屏**：实点「数据自检」→ problems 两条（含 R86「好消息」指引条）+ 原文
     技术行 + 12 表 chips。
2. **拍法坑记档**（已做并验过）：登录前工作台/设置页取数 401 → 「没加载出来/登录已失效」，
   登录后必须点「重新加载」——工作台与设置页两处注入 JS 都处理了。
3. **交叉印证顺手拿到**（已做并验过）：服务器启动时对坏库打的 auto 备份包在远端备份列表
   可见（`服务器最近一次成功备份：1 分钟前` + 包名）——R86 服务器侧隐形修复包的实拍交叉
   印证。
