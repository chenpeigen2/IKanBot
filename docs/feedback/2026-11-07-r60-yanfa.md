## 一、四件小修（各一条独立提交）

### ① 核销弹窗不居中 —— **已做并验过**

根因先确认了再动手：`styles.css` 里 `.main .content` 带 `page-in` 动画且 `fill-mode: both`，
动画的 transform 关键帧让 Chromium 把 `.content` 当成 `position:fixed` 后代的包含块，
遮罩的 `inset:0` 变成相对内容区——所以长页面上弹窗缩在右下、顶部被 sticky 页头压住
（r59/settle-modal.png 修复前实拍可见：页面顶部根本没被遮罩盖住）。

修法按倾向做了 **Modal portal 到 body**（`src/renderer/src/ui.tsx` 一处改动），不是单弹窗打补丁：
`position:fixed` 的另外两处本来就没事（`.menu-pop.fixed` 本来就 portal、`.toast-wrap` 挂在 `.content` 外），
改动只影响所有走 `Modal` 的弹窗。自验实拍（`docs/ui/r60/`，每张配了断言说明）：

- **settle-modal.png**：本轮要修的场景，订单详情收款页签 →「登记短款」——弹窗视口正中、遮罩盖整屏；
- **void-modal.png**（wide 弹窗）、**pi-preview.png / quotation-preview.png**（xwide 单据预览）、**order-new.png**（默认宽度表单弹窗）——四种形态无一回归；
- 补一句实话：渲染层断言没有现成接缝（e2e 是数据层、双模式测试走 IPC 桩，都不渲染 DOM），
  弹窗居中这条**没有自动化断言**，证据是修复前后同场景实拍对照 + 根因分析。

## 二、大件：单据存档簇（docs:）搬后端 —— **已做并验过**

### 搬了什么（以 ipc 里实际通道为准，先列了清单）

| 通道 | 远端模式现在怎么走 |
| --- | --- |
| docs:save | PDF 仍由**本机 Chromium** 渲染（htmlToPdf），字节经 HTTP 上传，存到服务器的 docs 目录（`IKAN_DOCS_DIR`，默认 `.tmp/docs`，布局与桌面 `data/docs` 一致） |
| docs:list / docs:listQuotation / docs:void / docs:nextVersion | 登记进 REMOTE_ROUTES，转发器直送服务器（JSON） |
| docs:openFile / docs:reveal | 服务端按相对路径回字节（POST /api/docs/read），桌面落地临时文件再开/显示；reveal 不带文件名（整目录）在远端给人话报错 |
| images:baseDir | sendSync 旁路收编进 handleSync（R46 挂账），覆盖率分母 119 → 120 |

### 判据收进 core（单一真源，不两份 SQL）

`electron/services/docs.ts` 的全部判据搬进 **`core/docs.ts`**（db 注入 + 目录注入），
桌面门面只剩「接本机目录」：版次 MAX+1 只增不减、纸面指纹存档前重算、CI 重叠闸门、
R42 路径守卫（盘符接回/拒目录外，**服务端同样守**）、存档串行队列（防并发双 v）、漏金额拒存
（这道从桌面 IPC 收进 core——HTTP 入口同一句话术）。服务端 Nest 模块只是 HTTP 门面。

### 测试（全程先红后绿，测试与实现同提交）

- **HTTP 冒烟 169 → 188（+19）**：save（字节上传落档、重版递增、版次过时拒存、漏金额拒存、无 token 401）、
  read 字节逐字节一致、路径守卫四例（`../../`、`D:\old-pc`、`/etc/passwd`、`docs/../../`）全拒、
  文件不在 404 说人话、CI 作废重出全链路。
- **双模式 116 → 128（+12）**：测试桩恒定字节 PDF，同一份单据本机存/远端存**取回字节逐字节一致**；
  远端登出后 docs:list 同样「请先登录」；两边存档账各是各的（本机查无 REM 档、后端查无 LOC 档）；
  时间账红线没踩——存档 createdAt UTC 存、`localDateOf` 按本地日显示不跨日（断言锁住）。
- **桌面 e2e 2298 → 2302（+4）**：小修②的门函数。重构本身让 2302 全绿（含 R42/R43/R45/R18/R34 的存档既有断言）。

### 过程里被测试抓出来的两个真 bug（都修了）

1. `assertCiNoOverlap` 从同步变异步后，**IPC 和 core 事务内两处调用没 await**——CI 重叠的复查
   从「落账前把门」退化成「飘在空中的 Promise」，重叠照样落账 + 未处理拒绝把进程炸掉。
   e2e R34 的「未确认时照样拦下重叠」当场红。
2. 服务端路由用 `@Header('content-type','application/pdf')` 时，**错误响应继承了这个头**——
   express 的 res.json 见「已有 Content-Type」不再改，400 的话术被客户端当 PDF 解成乱码。
   AllExceptionsFilter 现在强制错误体 application/json。

- **设置页与记账同步**：设置页数据来源卡改为「94/120（含单据存档：远端模式也能出 PI/CI 并存档）」，
