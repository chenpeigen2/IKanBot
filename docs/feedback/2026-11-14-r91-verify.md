**暴露面评估**（如实分层）：
- 截图直进是放大器：应用先挂工作台、health/stats 对坏库的查询还在主进程排队，settings.get
  被压慢——竞态高发。真实用户「工作台已停稳 → 点详情」两跳路径我跑 2/2 全中（主进程闲、
  s 几毫秒就回来）。
- **远端模式是真暴露面**：settings.get 走 HTTP 往返，公网 100–300ms 很常见，大概率输给
  150ms——而远端红条点「详情」恰是这功能的主要受众。研发报告与 r91 README 均未提这层。
- 滚了但输的次生窗口：两跳成功态 aTop=178/196 之所以好看，是 mode.get 晚到、来源卡随后
  长高把锚点从 0 顶下来的——若 s 与 source 都赶在 150ms 前就位，锚点会贴 scrollport 顶、
  卡标题被 sticky topbar 盖住（本轮 13 跑没拍到这个形态，纯读核推演，记小账）。

## 六、挑刺（均非打回项）

1. **锚点 effect 的时序竞态（本轮最要紧的小账）**：Settings.tsx:233–237 一次性 150ms 定时器 +
   :372 `!s` early return（锚点不在 DOM）+ `?.` 静默吞——三件套叠加成「输了就无声落到 R89
   挑刺 5 原状」。实测：直进 10 跑 3 中（run7 浮层铁证 scrollTop=0 / anchor=Y），远端模式
   settings.get 走 HTTP 大概率进同一条沟。修法很轻：effect 依赖 `[s]`（数据到位再滚）或对
   锚点做短轮询/重试。建议下轮顺手清偿，届时把直进与远端两态一并实拍。
2. **e2e R91 两条是源码串锁**：锁「字符串在同文件」不锁「滚没滚」——竞态不可见。与仓库
   renderer 无 DOM 工装的现状一致，实拍补位（本轮以带测量的 13 张实拍补得比以往更狠），
   可接受，如实记现状。
3. **「直滚到视口顶部」的说法与实况有微差**：实拍落点是 aTop=178–196（视口顶下方），靠的是
   来源卡晚加载长高把锚点顶下来——结果比字面「顶部」更好看，但这是时序巧合不是设计；
   两数据都快时锚点贴顶、标题被 topbar 盖住的窗口读核在案（未实测到）。纯外观小账。
4. **入库实拍只有成功态 1 张**：竞态失败态（st=0）与工作台起跳态没入库——现在 out/ 里有
   （wj91-twohop-run1/2/3、wj91-direct-run9/10、wj91-pure-run7），不追；下轮若修锚点，
   建议成败两态都入库。
