### ① 「水单拆分收款幂等」断言实况——桌面 8 条、HTTP 3 条，全绿，口径全对

任务说「桌面七条」——实际桌面节是 **8 条**（研发报告的「七条」是把「首次落两笔」「同键重放拿回结果+
流水不翻倍」各按一组数的少了一条；但 +8 的增量账本身是准的，不算虚报）。逐条念名：

1. 「水单拆分一次登记两笔」——动作本身通；
2. 「首次登记落了两笔流水」——两张单的 payments 数出来是 2，真落账；
3. 「同键重放拿回第一次的整组结果（不报错）」——**口径对**：重放拿到的是第一次那组单据（逐单比对
   `batchReplay[0].id === batchFirst[0].id`），且不报「同一张水单不能记两次」的错；
4. 「重放后流水数没变（整批只落一次）」——**口径对**：重放前后流水数相等，不翻倍；
5. 「换新键的新水单照常落账」——**口径对**：新键 + 新流水号 → 流水 +2（测试代码里还留着注释：
   「新键 = 新水单：流水号也要换」——研发说的测试自纠那一处，注释确实在）；
6. 「不传 request_id 的老调用不受影响（水单照旧整批落）」——**口径对**；
7. 「客户页水单拆分：提交带 requestId」——接线检查；
8. 「客户页水单拆分：打开弹窗就发号（newRequestId）」——接线检查。

HTTP 节三条：「HTTP 拆分收款落一笔」「HTTP 同键重放拿回第一次结果、流水不翻倍」「HTTP 换新键的新水单
照常落账」——真 HTTP 请求打到 `/api/orders/batchAddPayments`，重放结果比对 id、账面数流水，全绿。

我读了断言源码（`scripts/e2e-test.ts:12948` 起、`server/test/e2e.ts:1169` 起）：真建客户、真建两张单、
