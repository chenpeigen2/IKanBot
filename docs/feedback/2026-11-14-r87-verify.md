## 二、审计工具独立核验（实跑 + 口径拆解）

1. **实跑**：`npm run audit:http` → `总路由（controller 声明）: 108  功能断言引用: 108`，
   未引用清单为空。与研发口径一致。
2. **两个口径坑核实为真**：
   - dashboard/dashboard.controller.ts 确实一个文件挂三个 @Controller 块（`api/dashboard`、
     `api/report`、`api/export`，我逐行数过 @Controller/@Post），脚本按块切开逐块配对——
     e2e 里 `/api/export/csv`、`/api/report/monthly` 都有真功能断言（1034–1050 行），不是只挂在

     （`/api/files/images/r87-probe.png` 等 6 处），按参数段前缀匹配口径收得进来。
3. **我自己找了四个口径漏洞（当前全部无害，如实记账）**：
   - **单向对表**：审计只查「controller 路由 → e2e 有字面引用」，反方向（e2e 引用了 controller
     里不存在的路由）不报——将来路由改名后，旧测试变成打空气的死测试，审计不会红。我用一次性
     探针把 e2e 里所有 `/api/...` 字面量反查了一遍：不在 108 条里的只有 3 处，全是良性
     （参数路由前缀本身、探针归一化噪声、`/api/no-such-route`——那是故意的 404 负向测试）。
   - **字面引用≠断言**：判定是「路由名在 e2e.ts 正文里出现过」，写在注释里也算覆盖。我把注释
     剥掉重对了一遍：当前 **0 条**只在注释里的路由——今天干净，将来谁在注释里提一句就糊弄过审计。
   - **只认 @Post/@Get/@Put 单引号**：将来用 @Delete/@Patch 或双引号/无参装饰器，路由会静默
     漏出审计面（漏出的方向是「少报」，审计照样全绿）。grep 过 server/src：当前无 @Delete/@Patch、
     无双引号 @Controller。
   - **每个域目录只取第一个 *.controller.ts**：当前 16 个域恰好各一个，将来一个域挂第二个
     controller 文件就漏。
   以上四个都是「将来改坏了会不会漏报」的潜伏口径，不是今天的误报。记一条小账（不挡放行）：
   建议下轮顺手加反方向对表 + 注释剥离，各 10 行的事。

  （见下），风险低。
- **机制解释拆解（自洽成立）**：styles.css 119–123 行 `.app { grid-template-columns: 208px 1fr }`
  + 275 行 `.content` 左右 padding 16px（合计 32）——容器 = innerWidth − 208 − 32 ± 2px 噪声；
  两态窗口差 1440 − 1224 = **216**，容器差 1198 − 982 = **216**，overflow 差 498.117 − 282.117 =
  **216**（/samples 同差）——三个 216 严丝合缝，w 恒定、只有容器变，研发的机制叙事与我的实测

- 顺手记一个真机怪状（不影响结论）：屏幕 1440、availWidth 也是 1440，请求 1600 宽的窗口被
  macOS 钳到 innerWidth **1224** 而不是 1440——macOS 的窗口适配规则没完全说清，但研发口径的
  数字与实测一致；「宽态 = 窗口真拿到 1440」在机制上成立，何时发生没钉死，正是「两态漂」还留
  着的那口气。
- **判断：不是第三态、不是回归**——20 跑只出常态一种值，健康指标全 0，常态值与基线逐字节一致。
