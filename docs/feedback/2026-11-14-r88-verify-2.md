## 八、挑刺（本轮返工的新锐边，均非打回项）

1. **B2 精确匹配对参数化路由的误报锐边**：`serverRoutes.includes(r.path)` 是全等匹配，
   而当前 REMOTE_ROUTES 100 条 path 全为具体路径（无 `:参数`、无 query——我核过），无实例。
   将来若有远端 path 指向参数化控制器路由（如 `/api/files/images/x.png` ↔
   `/api/files/images/:name`）会误报红。方向保守（宁可误报不漏报），CI 挡下人工看一眼
   即可，但届时别当 bug 修——记小账。
2. **controllerRoutes() 是两份复制的同一段代码**：audit:ipc 注释自称「与 audit:http
   同源口径」，实为**逻辑同源、代码重复**（两脚本各持一份一模一样的提取函数）。将来只改
   一边（比如支持 @All/@Head 装饰器）另一边静默漂移，B2 与反方向的「server 路由真相」就会
   分叉。建议抽公共模块——小账。
3. **B2 正则要求 path 是入口第一个字段**（`\{\s*path:`）：字段重排（args 写前头）的条目
   仍被条目正则计入 REMOTE_ROUTES（100），却从 remotePaths 掉出去，B2 对该条失明——且
   当前**没有** remotePaths.length 与 REMOTE_ROUTES 数的守门比对。我实测今日 100=100
   对齐，但无闸保证将来还对齐——小账。
4. `ALLOW_EXACT` 里 `/api/no-such-route` 是故意 404 负向测试的专用口子：将来若有人塞的
   死路由恰好叫这个名会被豁免。可接受（名字即负向测试语义），如实记。
