## 二、三个不变量（每条都拿真数三处对）

**① 「这单一共还欠客户多少钱」三处一个数 —— 过**
- 单笔：SO20261021001 订单详情卡「待收 **USD 4,805.00**」= 客户页订单行「待收 USD 4,805.00」= 工作台待办「已收 3000.00 / 待收 4805.00」（r11-order123 / r11-cust-detail / r11-dashboard）。
- 公司级（转单抵扣**之后**的新口径）：工作台 **CNY 62,741.25** = 我手算 (4805+3120+850+0)×7.15 = 62,741.25，打样单已抵扣不再计；客户页 Acme「未收 **CNY 56,663.75**」= (4805+3120+0)×7.15，加 Nordic 850×7.15=6,077.50，56,663.75+6,077.50 = 62,741.25 ✅ 对得上。
- 转单前的 63,956.75 也手算过（含打样 1,215.50），该进的进、该扣的扣。

**② 「这单到底赚了多少」三处一致 / 三处都诚实 —— 过（附一条新问题 N-4）**
- 订单 123 详情「毛利 USD 3,150.00 / 成本 4,425.00」——成本录全了敢给数。
- 工作台「本月毛利 **—**」+「本月有单成本没录全，毛利不可信（宁可给你『—』）」；报表「累计毛利 **—**」+ 黄条点名「有成本没录全的单：2026-10（1 单）…补录入口：订单 → 商品明细 → 成本」。查库：订单 126（TS-900）成本没录，就 1 单 → **三处口径同一个，两处都诚实给「—」**。
- 客户页 Acme「累计毛利 CNY 33,055.17」= (3150+1439.30+33.10)×7.15，Acme 三单成本都录全，敢给数，自洽。
- ⚠ 但这轮转出来的抵扣单暴露了毛利口径的岔子，写成新问题 **N-4**。

**③ PI / CI / 报价单 / PL 四张纸合计 —— 过（口径都在纸面上写清楚）**
- PI 纸面 `TOTAL / 合计 900 … 7805.00`；
- CI 纸面 `TOTAL / 合计 900 … 7805.00 | Total Payable: USD 7,805.00`，**生成前的确认框还专门印了一句「CI 合计与 PI 合计一致（USD 7,805.00），可以直接用」** —— 这句我爱看，谁也别想悄悄差一张；

## 三、本轮新发现

**N-4【很重要】抵扣转出来的订单，毛利是个「漂亮的假数字」**
- 场景：客户确认样品，我点「样品费抵扣，转订单」，转完跳进 SO20261021005。
- 现在的做法：这单**订单金额 USD 50.00、含费用合计 USD 0.00、待收 USD 0.00**（费用栏 −50 抵扣），可详情卡上「**毛利 USD 33.10 / 成本 16.90**」——它是拿货值 50 减成本算的，把那行 −50 的抵扣当成了「过手费用」给忽略了。
- 痛在哪：这单我**一分钱都收不到**（0 元单），报表里它的销售额也确实是 0（转单前后本月销售额都是 112,076.25，一分没涨），客户页 Acme「累计毛利」却把这 33.10 加进去了。**订单页 +33.10、报表口径 −16.90，同一单两个毛利，差 50 USD**；等哪天成本补齐、报表敢给数，两个数就正面撞车。这正是我最怕的「有地方给漂亮数字」。
- 想要什么：抵扣单的毛利要么按「这单实际能收多少」老实算（0 − 成本），要么在毛利旁边写清楚「含样品费抵扣 −50，口径与报表不同」。**别让一个收 0 元的单显示赚钱。**
- 重要性：**很重要**（算钱口径，且是我连续三轮都在盯的那条线）。

**N-5【有点烦】筛选没结果时，提示话说「还没有打样单」**
- 场景：我在打样列表把状态筛成「待寄出」，碰巧一张都没有。
- 现在的做法：空列表中间写「**还没有打样单。客户要打样的时候点右上角『新建打样单』。**」——可我明明有 1 张（r11-rate-guard.png 第一次误截那张：共 0 张打样单 + 这句话）。
- 痛在哪：我会以为单子丢了，去翻数据库、去问研发；实际只是筛选条件的问题。
- 想要什么：有筛选条件时说「这个筛选条件下没有打样单」，把条件亮出来；真的一张没有才说「还没有打样单」。
- 重要性：**有点烦**（但会吓人一跳）。

**N-6【有点烦 · 待观察】404 有一次没生效，落到工作台**
- 场景：第一发 `scripts/shot.sh /xyz r11-notfound` 截出来是**工作台**（r11-notfound.png），隔几分钟重跑同一命令就是标准 404 页（r11-notfound2.png），之后没再复现。
- 痛在哪：如果这是启动时路由还没挂上、手输网址会被吞掉的情况，那我开机第一件事输错网址就会看到工作台，以为地址没错。
- 想要什么：研发看一眼启动时 `hash` 设置与 HashRouter 挂载的先后（`electron/main/index.ts:68` 是 did-finish-load 后直接改 hash），有没有可能被吃掉；确认没问题就跟我说「是你截图的时序问题」，我把它划掉。
- 重要性：**有点烦**（一次，没复现，先记着）。

**没坏的（原来好用的这轮都还好）**：工作台四卡与最近订单金额（USD 7,805.00 = 订单详情含费用合计 = PI/CI 纸面 = 存档版金额）、报表三个导出按钮与黄条补录提示、订单详情五个页签、打样列表横向滚动、报价列表「看订单」入口、客户页四张统计卡——本轮都没被这 8 条改出毛刺。

**测试痕迹说明（不是产品问题，`npm run seed` 全清）**：本轮我动了库——把 Q20261021001 手工标成 converted（验 N31）、把打样单日期改成 9-20/9-25（验催收圆点）、界面真实转出订单 SO20261021005、真实存了一版 PI（doc_versions 一行）。**没跑回滚，你打开程序会看到这些，是我在验。**
