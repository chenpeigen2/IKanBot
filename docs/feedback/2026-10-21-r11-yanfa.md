## 一、N-4 抵扣单毛利虚高（已修 · 最重要）

**哪个是对的**：她问「订单页 +33.10、报表口径 −16.90，同一单两个毛利」。
**答案：报表口径是对的**（含费用合计 0 − 成本 = 负数）。订单详情原来那 33.10 是假的——它拿「货值 50」算，可这 50 被那行 −50 的样品费抵扣抵平了，客户一分钱不给，订单实际含费用合计就是 0。收 0 元的单不许显示赚钱。

**改法**：把毛利口径统一到「实收口径」。协调员裁定：+33.10 和 −16.90 两个都不对，**正确口径是实收金额减成本**，我据此推导最终公式。

**N-4 最终公式（下轮复核这段推导）**：
```
毛利 = 货值 + 负数费用行 − 成本
     = (货值 + 正向费用 + 负向费用) − 成本 − 正向费用
     = 含费用合计（grandTotal） − 成本 − 正向费用
```
为什么要减掉「正向费用」：`grandTotal` 已含运费/保险这类**正向**费用，但它们是**代收代付**——客户多付我这笔，我随后要付给货代/保险公司，不落我口袋，所以不进毛利。而**负向费用**（样品费抵扣 / 折让）是客户从应付里扣掉的、**真让掉的钱**，必须从毛利里扣。
- 抵扣单：货值 50 + 费用行(−50) = 含费用合计 0；毛利 = 50 + (−50) − 成本 = **0 − 成本 = −成本**（收 0 元就显示亏成本，不再拿货值凑漂亮数）。
- 普通单：只有正向运费/保险，负数费用行 = 0 → 毛利 = 货值 − 成本，**和原来一模一样**（现有 364 项断言不红，已验）。
- 公式落地：`electron/services/money.ts` 的 `computeOrderMoney()`，`profitRaw = goodsValue + negativeCharges − totalCost`。这是**唯一入口**，结构没动，只改了这一行的算法。

原来 `毛利 = 货值 − 成本`（漏掉负费用），改成上面的公式。正向费用（运费/保险）是代收代付的过手钱，维持原口径不进毛利；**负向费用（抵扣/折让）是真让掉的钱，必须扣**。改动只在 `electron/services/money.ts` 一处（唯一真源），四个页面全部自动跟着变，不存在「改了报表没改工作台」。

- 改的文件：`electron/services/money.ts`（`computeOrderMoney` 加 `negativeCharges`，`profitRaw` 把负费用算进去；`OrderMoney` 增 `negativeCharges` 字段）。
- 界面：订单详情毛利卡在有抵扣时多印一行「**已扣抵扣/折让 USD −50.00（毛利不再按货值算，收 0 元的单不显示赚钱）**」——把口径写在纸面上，不留悬案。改的文件 `src/renderer/src/pages/OrderDetail.tsx`。
