## 三、这 4 轮真正解决的问题（不是"变好看了"）

1. **视觉噪音**：一屏 10 种字号 → 2 种；4 张统计卡 4 种颜色 → 统一规则（一屏最多 1 张强调卡）
2. **状态不可辨**：紫色/青色幽灵色删除；状态色按维度分家（钱 vs 货不再共用一个颜色）
3. **表格不可用**：订单表/打样单表从必然横向滚动 → 溢出归零，11 列全显
4. **编号形同虚设**：PI 号被截成 `PI202610210…`（5 行前缀一样）→ 完整显示
5. **操作列读不懂**：「编辑删除」连成一个词 → 形态统一 + 分隔
6. **可读性硬指标**：辅助文字对比度 2.58:1（不合格）→ 改到达标值
7. **图标不统一**：侧栏 8 个 Unicode 字形（◧▤▣☰▦⚙✎✂ 字形重量不均）→ 全部换 SVG
8. **表单语言混乱**：同一弹窗 label 一半双语一半中文 → 表单一律中文，双语只留给单据

## 五、协作沉淀（已写进 .pi/agents/ 定义）

**UI 审查官**
- 必须实际截图逐页看（11 页 + 6 弹窗 + 4 打印单据），不许只读 CSS 出报告
- 每条问题要指到文件+行号 + 量化依据（像素扫描、computed style）
- 结论矛盾时**主动更正自己**（R2 更正了 R1 的一条误判；R4 发现 P8 是旧截图）
- 明确写"这条已经一致，本轮不改"

**研发**
- 先落 token 再改组件；只动 `styles.css` + `pages/*.tsx` + `ui.tsx`
- `documents.ts` / `services` / `money.ts` 硬红线（单据排版归审查官、业务计算归周文娟）
- 每条改动要有前后对比截图；typecheck 0 错 + 断言全过
- **边做边写报告**（R4 起生效，两次超时白干的教训）

**协调员**
- 不轻信 agent 结论：单据列错位（R2 S1）经实测判定为误报，**拦截了研发去改正确代码**
- 同时在 429 中断后发现了研发误改造成的**真错位**，已修复并加 6 条列数断言锁死
- 修掉 `node-sqlite3-wasm` 残留锁导致的 `database is locked` 启动失败（自愈）
