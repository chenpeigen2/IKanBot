## 二、这 6 轮真正修掉的东西（不只是"按钮好不好看"）

### 金额口径：从"六个地方六个数"到"一个入口"
第 5 轮使用者报了三次"三处一个数"没解决，根因是**每个页面各写各的 SQL**。
第 6 轮协调员建了 `electron/services/money.ts` 作为唯一真源（`computeOrderMoney` /
`listOrderMoney` / `totalReceivable` / `customerReceivable`），11 处消费方全部改调它。
此后每轮使用者都亲手拿一个数三处对，**全部对上**。

### 汇率纪律：拒绝"系统替人编造凭据"
报价单汇率原本预填 7.2，转订单时还会用转单当天**编一个锁汇日期**，PI 上印
`1 USD = 7.2 CNY (2026-10-20)`——三个月后老板查，系统会一本正经说自己那天去钉盘锁过。
现在：报价单/订单/打样单**一律留空手填**，带**真实汇率日期**随单传递，
老数据无日期时**宁可报错也不编**（有断言锁死）。

### 算错钱的两个真 bug（都是被使用者实测抓出来的）
- **CI 与 PI 合计打架**：同一张单 PI 印 5,540、CI 印 5,310（CI 的运费保险默认是 0）。
  货代按 CI 报关、银行按 PI 付汇——**走信用证这就是不符点**。
- **抵扣单显示"漂亮的假数字"**：样品费抵扣转出的 0 元单，订单详情毛利 +33.10、报表口径 −16.90，
  同一单两个毛利差 50 USD。根因是拿货值减成本、把 −50 抵扣当过手费用忽略。
  协调员裁定正确口径 = **毛利按"这单实际收得到多少 − 成本"**，
  研发改为 `货值 + 负费用 − 成本`（正向运费保险是代收代付不进毛利，负向抵扣/折让是真让掉的钱要扣）。

### 单据留痕
PI / CI / 报价单 / PL 四张纸的合计口径统一；版本号区分"待存为第 N 版"与正式号；
每版 PDF 存档可直接打开；报价单可编辑且**报价号不变**、留痕"数量 500 → 700"。

### 打样环节从零到闭环
样品费/快递费/工厂打样费**三笔分明**（应收 / 垫付 / 成本），公司净垫 = 成本 − 已收回；
未收的打样费进工作台待收与催收提醒；打样可一键转订单（样品费可抵扣成负费用行）。

### 账不能被删
有款的订单只能**作废**（收款记录、操作历史、存档全留）；已转订单的报价单删不掉（提示改「已失效」）；
有记录的客户删不掉并给出中文说明与替代方案。

## 三、两个 agent 的心智沉淀（已写进 .pi/agents/ 定义，后续轮次自动继承）

**使用者（waizhuan）**
- 三个不变量清单：待收三处一个数 / 毛利三处一致 / 四张纸合计一致 —— 必查
- 只信代码不信报告，每条自己点
- 25 分钟硬预算，做不完如实写"验到哪儿"

**研发（yanfa）**
- **金额口径唯一真源**：同一数只准有一个计算入口，改任何一处 grep 所有消费方
- **报告纪律**：写"已做"必须自己点过、能截图证明；做不完写明原因，不许超时丢在半路
- 一轮只做 3~5 件最要命的
- 截图只用带超时的 `scripts/shot.sh`（裸跑 electron 会挂死会话）
