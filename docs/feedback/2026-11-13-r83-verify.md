## 三、口径同源复核（dataHealthCheck vs inspectRestoredDb）

逐闸对表（HEAD 版 core/settings.ts:371-387 vs core/backup.ts:354-395）：

| 闸 | 备份/恢复探针（inspectRestoredDb→assertDbProbeUsable） | 数据自检（dataHealthCheck） | 同口径？ |
|---|---|---|---|
| 自检 | `quick_check !== 'ok'` → 拦 | `quickCheck === 'ok'` 计入 ok | **同**（比较字面量与方向一致） |
| 版本 | `v > LATEST_DB_VERSION` → 拦 | `ver <= LATEST_DB_VERSION` 计入 ok | **同**（同一个 LATEST_DB_VERSION，都 import 自 electron/db/schema，单一来源） |
| 核心表 | COUNT orders+payments，查不到就拦 | 12 张表逐一 COUNT（含 orders/payments，超集）；表缺失靠 COUNT 抛错兜 | **同语义**，自检清单更全（搬迁对账同款 12 表，行数还顺带给用户看） |

口径真同源，且自检是探针的超集——「别让两条路各说各话」这个 R67 教训在活库版里守住了。
一个代码注脚（不挡放行）：第三闸写成 `(tables['orders'] ?? 0) >= 0` 是恒真式，实际兜底是
COUNT 抛错——语义等价，但这行的字面意思是「orders 行数 ≥ 0」，读者会以为有校验其实没有，
下轮顺手改成显式判断或删掉。

**但失败态有一条暗沟（实测，挂账不挡放行）**：损坏口味决定走哪条路——
- quick_check 能返回错误行、COUNT 还能跑（freelist/索引级损坏）→ **内联红框**，承诺的

  角错误 toast「数据自检没跑出来：database disk image is malformed」——英文原句、没有
  「先别录单」（out/shots/r83-verify-settings-redbox.png）。catch 分支的话术建议下轮补一句
  「请先不要录单」，与 ok=false 分支对齐；
- 版本超前 → 程序根本开不了库（migrate 抛错，防呆设计本来如此），按钮到不了，红框的这个
  分支在本地实际靠启动拦截兜住。
