## 二、逐项亲验记录

### ① 断言实况——一条全绿，接线 grep 风格与 R76 同款

e2e R76 段内追加一条（scripts/e2e-test.ts:264）：

`check('R77 毛利卡：同一份清单的直达链接（不可信的原因可点排查）', custSrc76.includes('点单号直达）') && (custSrc76.match(/rateMissingList/g) || []).length >= 2)`

- `rateMissingList` 在 Customers.tsx 必须 ≥2 处（成交额卡 + 毛利卡）；
- `includes('点单号直达）')` 带**右括号**——成交额卡的话术是「点单号直达，」（逗号），
  毛利卡是「点单号直达）」（括号），这条断言只认毛利卡那处，不是混着数。
- 实跑日志 ✓（2531 = 2530 + 1 的那一条）。接线 grep 锁接线，形态由实拍兜底——
  与 R71/R76 既有风格同款，报告也如实自称「接线断言」。

### ② 同源复核——毛利卡没有另写清单数据

Customers.tsx diff（863-883 行）：毛利卡直接 map `detail.stats.rateMissingList`，
与成交额卡同一份数据、同一个 `navigate('/orders/'+orderId)`，无新查询、无第二份算法；
「有 N 单汇率没填」的 N 仍是同一个 `rateMissingOrders` 字段（R76 对齐后的口径，
哨兵含在内）。同源成立。
