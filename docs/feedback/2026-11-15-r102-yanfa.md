# R102 研发报告 —— 审计正向覆盖口径统一：统一当场暴露并补锁四条真缺口

日期：2026-11-15。基线 v0.5.44。每条标「已做并验过 / 已做但没验 / 没做（原因）」。
本轮改动在**审计脚本与 server 测试**（无渲染层改动：无 UI 形态，无截图义务，证据为审计
输出与断言结果）。

## 一、做了什么

1. **正向覆盖口径统一**（已做并验过）：scripts/audit-http-coverage.cjs 的 `covered()`
   从「字面量 includes + 参数前缀」两套旧写法统一到共享 `matchRoute()`（与 R101 收口的
   反方向同款：`:param` 只吃一段、逐段相等）。R101 只收了反向——其复验明说「正向仍按
   参数前缀匹配……可另开一轮统一」，本轮就是那一轮。
2. **统一当场暴露四条真缺口，当场补真功能锁**（已做并验过）：旧口径的子串/前缀误配把
   四条路由误计为已覆盖——统一后审计当场报 4 条未覆盖：
   - `orders/delete`（被 addItems 类长字面量子串误配）→ 空单整单删除锁（get 回空体）；
   - `orders/addItem`（singular——e2e 只打过复数 addItems）→ 单条落库锁（get 复核款号
     与数量）；
   - `orders/lastExchangeRate`（被 lastExchangeRateInfo 子串误配——R102 复验勘误：四条全是误配类，记法已按复验改准）→ 全局最近一次下单汇率锁；
   - `samples/list`（被 listPayments 子串误配）→ 列表带回刚建打样单锁（形状 + 内容）。
   四条断言进 server/test/e2e.ts（R102 段，自带客户/订单/打样单数据）。
3. **当场抓到并记档一个断言通道坑**（已做并验过）：lastExchangeRate 返回顶层原始类型
   JSON（数字）——supertest 对顶层 number 不进 `body`（text="7.2"、body={}），首轮断言
   被 `{}` 坑红；改走 `Number(text) === 7.2` 的 text 断言。坑记进本轮报告与断言名。

## 二、验收数字

- HTTP 冒烟 241 → **245**（+4 即四条新锁）；e2e 2560 · 双模式 146 · 数据层 82（不变）；
  typecheck 零错误；audit:http **108/108**（逐段语义下的全覆盖，不是子串放行的 108）；
  audit:route-match 18 项全过；audit:ipc 132/132·100。
- 无 UI 形态（零渲染层改动），证据为审计输出与断言结果。

## 三、红验证

本轮的红就是审计自己：统一前正向报 **4 条未覆盖**（exit 1）——那 4 条是旧子串/前缀口径
误配放行的真缺口，红得有名有姓（本报告第一节逐条列了误配方式）；补锁后 108/108 全绿。
另 lastExchangeRate 首版断言被 supertest 顶层原始类型坑红（body={}、text=7.2）——改 text
断言后绿，两轮输出均留档 out/http-r102*.log。
