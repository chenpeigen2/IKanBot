## 二、远端 catch toast 实拍独立复现（本轮主菜，两轮全中）

**服务器**：`IKAN_PORT=8801`（起前 lsof 查空闲，0 监听）+ 健康空库（IKAN_SQLITE_FILE /
IKAN_IMAGES_DIR / IKAN_DOCS_DIR / IKAN_BACKUP_DIR 全重定向到 out/wj95-remote/）+ bootstrap
wenjuan / Secret#123 / 周文娟。日志两行在案：「已创建首个用户 wenjuan（显示名：周文娟）」
「已启动 …（数据后端 sqlite，已接 110 个接口）」，healthz `{"ok":true,"db":"sqlite"}`。
两轮各自起各自的新空库服务器。

**shot A（seed 登录）**：`IKAN_MODE=remote + IKAN_REMOTE_URL=http://127.0.0.1:8801 +
IKAN_AUTH_FILE（全新文件）+ IKAN_CONNECTION_FILE + IKAN_DATA_DIR` 全重定向，注入 JS
`window.api.mode.login('wenjuan','Secret#123')`——auth 文件落盘
`{"enc":"djEw…","username":"wenjuan","displayName":"周文娟"}`（token 是服务器签的，登录真成）。
shot A 画面停在「设置没加载出来/登录已失效」+ 一串 401 toast——登录前取数 401 的坑（r94
负验证同款），shot A 目的只在落 token，不追求画面。

**shot B（宕机点自检）**：同一 auth 文件起新实例 → mount 时服务器活着，settings.get 成功
（「已登录：周文娟（wenjuan）」+ 备份卡 + 按钮全渲染）→ **shell 于 shot B 启动后 5 秒定点
kill 服务器**（kill 后 sleep 1 秒 lsof 确认 8801 零监听）→ IKAN_SHOT_JS 固定睡 8 秒后
**fresh `querySelectorAll('button')` 按文案找「数据自检」**点击（不持旧引用）→ 主进程管线
extraJs resolve 后 +2s + 探针 + capture，落点在**点后约 2～3 秒**——与 r95 README「capture
必须落在点后 ~3 秒内」吻合，toast 寿命 5200ms（ui.tsx:510 实核）内。

**两个拍法坑的避开方式**：① 不用 fetch 轮询测死亡——kill 与 click 之间留约 7 秒确定性间隔
（kill 在启动+5s、click 在注入+8s ≈ 启动+12s），死亡先于点击必然成立；② capture 落点由
主进程管线固定（点后 2～3 秒），两轮都落在 5200ms 窗内。**两轮全中，零绿框废片。**

**toast 全文（两轮逐字一致）**：

> 数据自检没跑出来：连不上后端 http://127.0.0.1:8801（fetch failed）。
> 确认后端已启动、地址写对了没有——都在「设置 · 数据来源」。后端没起来时，可以先把数据
> 来源切回「本机」。——请先不要录单，立即联系技术支持。

与入库图 `remote-toast-server-down.png` **逐字对照**：除端口 8800→8801 外**每个字都一样**，
含换行结构（「（fetch failed）。」后换行）与尾巴「——请先不要录单，立即联系技术支持。」。
与我读到的源码链也逐字对上：`electron/remote/client.ts:158-160` 的「连不上后端 ${remoteUrl}

## 六、挑刺（均非打回项）

1. **尾巴话术的轮次归属写错了：是 R84 修的，不是 R92**。r95 README 写「尾部即 R92 修的话
   术」，研发报告写「toast 全文含 R92 修的话术尾巴」，提交信息写「R92 话术修复在真实宕机
   场景兑现」，backend-plan R95 条目写「——R92 修的 catch 话术」——**四处同一笔误**。git
   考古定案：`git log -S` 锁定全串「——请先不要录单，立即联系技术支持。」由 **eb98869（R84）**
   引入（R83 只有前半句「数据自检没跑出来：…」）；R92 的正身是锚点竞态修复
   （`Settings.tsx:233` 注释自证），从没碰过 toast 话术。最打脸的是 **r95 README 自己的断言列
   写的就是「R84 段…源码锁」**——同一张表里前后两处归属打架。证据本体无损（toast 实拍真、
   尾巴真、三态表其余两处与 R84 锁引用都对），但这是四处协同的事实性笔误，不是手滑：
   下轮把四处一并改回「R84」。
2. **shot B 的路由没写进配方**：入库图构图是 `#/settings?scroll=backup` 锚点位（我第二轮同
   路由逐块复刻成功），但 r95 README 拍法段没写路由——第一眼照配方拍 plain `/settings` 页
   顶也能拍到 toast（按钮在 DOM 就能点），可构图对不上会让人怀疑自己拍错。配方补一句路由
   省一坑。
3. **「mode 信息来自本机 connection.json」措辞不贴拍法实况**：env 钉住（IKAN_MODE /
   IKAN_REMOTE_URL）时 mode 来自环境变量（`electron/mode.ts` envLocked 优先于文件），
   connection.json 是无环境变量时的产品常态路径。r95 README「拍到的场景顺带证实」段的这半
   句在自家配方下不成立，改成「来自本机 mode 配置（env 或 connection.json）」更准。
4. **日备闸 ~9 秒首包的行为顺带记录**：健康空库服务器启动后约 9 秒就打当天第一包（0.0 MB），
   「备份卡内容随 mount 时机在『还没有』与『就在刚刚』间摆」——不影响 toast 主证据，记档
   防将来有人拿备份卡内容对不上当翻案依据。
