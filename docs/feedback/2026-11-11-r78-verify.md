- **渲染接线一条**：✓ R78 毛利卡（`includes('missingCostList') && includes('点单号直达补成本')`）
  ——接线 grep 锁接线，形态由实拍兜底，与 R71/R76/R77 同款风格。
- 小注：前两条断言名没带「R78」轮次号（只有第三条带），grep 字面「R78」只中一条——
  R73 敲过「断言名带轮次号」的规矩，这两条漏了。极小，下轮顺手；报告本身描述如实
  （「客户统计段两条口径断言 + 渲染接线一条」），不算虚报。

### ② 同构复核——与 rateMissingList 逐位同构，同一份 rows

- core/customers.ts:391-393：`missingCostList = rows.filter((r) => r.missingCostItems > 0)
  .map(...)`——**同一个 `rows`**（isBillingStatus 过滤后的 listOrderMoney 行），过滤条件
  与既有 `missingCostOrders` 计数逐字相同（同一个 filter 条件复制），计数与清单永远
  不会分叉；map 出的 snake 字段（customer_id/order_id/order_no/currency/missing_items）
  与 rateMissingList 同模式，多一个 missing_items。
- electron/db/mappers.ts：`Array.isArray` 守卫 + 逐字段转 camel（customerId/orderId/
  orderNo/currency/missingItems），与 rateMissingList 的转换同款；types.ts 的
  CustomerStats 补了类型。三处（core→mapper→类型）与 R76 逐位对称，「同构」成立。

## 三、疑点 / 观察项（都极小）

## 四、没验的（原因）

1. **交互场景连测**（点单号 → 订单详情补成本 → 返回毛利恢复数字）：需要交互式
   electron，纪律禁止；机制与 R76/R77 已验的链接完全同一份代码路径。
2. **sweep 九路由基线**：无重跑手段，信任提交信息；毛利卡在详情弹窗内。
3. **红态**（清单空/满边界）：客户统计段 fixture 已覆盖「有缺成本单」正例 +
   R76 的「不缺为空」反例，同构字段无需另造。
