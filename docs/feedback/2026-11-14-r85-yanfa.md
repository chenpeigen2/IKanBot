# R85 研发报告 —— 数据自检的远端路实弹（R83 复验挂账#1 清偿 + R84 复验小账）

日期：2026-11-14。基线 v0.5.26。每条标「已做并验过 / 已做但没验 / 没做（原因）」。
本轮**桌面与 core 零代码改动**——变的是 server 测试、文档与远端路的实拍证据。

## 一、做了什么

1. **server e2e 给数据自检补功能断言**（已做并验过）：R83 复验只给 `POST /api/settings/health`
   锁了路由数（110 含「设置自检 1」），ok/quickCheck/version/tables/problems 全没锁——
   problems 若被响应包装层无声丢掉，远端红框就退回 R83 的一句英文。补两条：
   - 「POST /api/settings/health 200：ok/quick_check ok/版本/12 表全带」
   - 「problems 过远端通道（健康库是空数组不是 undefined——丢了远端红框就退回一句英文）」
2. **定向红验证**（已做并验过）：controller 临时剥掉 problems 字段（模拟「响应包装层无声
   丢字段」）→ 重跑 HTTP 冒烟 → 「problems 过远端通道」**✗ 红、exit 1**；还原后 226 全绿。
   篡改现场与还原都用 git diff 核过（还原后 controller 与 HEAD 零差异）。
3. **远端模式 UI 实拍两态**（已做并验过，docs/ui/r85/，拍法照 R61）：
   - **绿框**：真起后端编译产物（独立空库 + bootstrap wenjuan）+ 桌面 IKAN_MODE=remote
     注入 JS 真登录 → 「重新加载」→ 实点「数据自检」——12 表行数**全是 0**，本机库同屏
     可证 orders=4：「谁的数据显示谁的健康」的远端半句实锤；远端备份卡形态同框。
   - **红框**：服务器换 freelist 坏副本（header 32–35 = 00 ff ff ff）再实点——problems
     人话 +「自检原文（给技术支持看）」技术行 + 12 表 chips **经 HTTP 通道原样渲染**。
   - 拍完临时库与 auth 文件全删（IKAN_AUTH_FILE 指向全新文件保证登录卡从「未登录」开始）。
4. **R84 复验小账两条清偿**（已做并验过）：① docs/ui/r84/README.md 坏库配方字节序笔误
   改准（「ff ff ff 00」→「00 ff ff ff」，大端 0x00ffffff，只有这个序能复现截图里的
   invalid page number 16777215）；② sweep 九路由随本轮全链复跑、与基线一致。
