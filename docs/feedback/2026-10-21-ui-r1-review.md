## 一、总体印象

这套界面的**信息结构是对的**——业务员该看的东西都在，页面骨架也统一，`.card` / `.stat` / `.tag` / `.modal` 这几套组件都有模子。问题不在"缺设计"，在**没有规范**。

具体说三句话：

1. **颜色在替数字说话。** 工作台一屏 4 张统计卡用了蓝、黄、黑、绿 4 个颜色，报表页同样 4 个，待办圆点里还藏着 `#7c3aed` 紫和 `#0891b2` 青。4 个抢眼色并排 = 没有重点，扫一眼反而找不到最重要的那个。
2. **同一种东西长得不一样。** 收款状态在订单列表是彩色标签，在报价列表是下拉框，在订单详情页顶部是标签、右侧又是下拉框（**同屏两种形态**）。业务员每换一页就要重新学一次这个系统。
3. **字号和间距没有刻度。** 工作台一屏里同时出现 **10 种字号**（16/17/25/20/14/13.5/13/12.5/12/11.5/11），样式表里间距从 2px 到 44px 用了 24 个不同值。中文 13.5px 在 Windows 125% 缩放下发虚，一天看 8 小时是能感觉出来的。

好消息：空状态做得比预期好（"当前筛选条件下没有订单…单子没丢——把搜索框或状态页签清空就能看到全部。"），别的地方照这个标准抄就行。

## 二、系统性问题（跨页面）

### S1. 字号没有刻度，一屏 10 种字号同时存在

- **现象**：`styles.css` 里 `font-size` 出现 13.5px（body/`.nav-item`/`.price-calc .total`）、14.5px（`.modal-head`）、12.5px（`.timeline-main`/`.sku-matrix`/`.price-calc`）、11.5px（`.tag`/`.hint`/`.stat-hint`/`.brand-sub`/`.sidebar-foot`/`.picker-meta`）等半像素；页面里还散着内联 `fontSize: 13.5`（`Customers.tsx:274,418`、`EditOrderModal.tsx:326,380`）、`fontSize: 13`（`OrderDetail.tsx:602,726`）、`fontSize: 10`（`OrderDetail.tsx:859`）、`fontSize: 22`（`Products.tsx:493`）。
- **量化依据**（运行时 computed style 实测）：工作台一屏出现 **10 种字号** `16, 11.5, 13.5, 17, 13, 12, 25, 20, 14, 12.5`；报价页 8 种。半像素（13.5/12.5/11.5/14.5/10.5）在 125% 缩放下落到非整数像素栅格，中文笔画会发虚。
- **为什么是问题**：字号不是审美问题，是**可读性预算**。同一屏 10 种字号意味着没有一个"默认"，看表格时眼睛无法预判该往哪看。半像素中文是典型的"看久了眼睛酸"来源。
- **改法**：见 `design-system.md` §2。落地 3 步：① `body` 的 `font-size: 13.5px` → `var(--text-base)`（13px）；② 新增 `--text-xs/sm/base/md/lg/xl/display` 变量；③ 全量替换 13.5/12.5/11.5/14.5/9.5（`styles.css:43,60,68,89,109,126,261,344,353,443,470,484,536,547,564,600,608,793,890,895,936,1063,1089,1115,1121,1136`）。**打印单据 `.doc-page` 的 pt 字号不动。**

### S2. 颜色没有 token，状态色散落硬编码，一屏 4 个抢眼色

- **现象**：
  - `styles.css` 里有 **48 处裸 hex**，其中与状态相关的有：`--amber #b26a00`、`.tag.amber`、`.reminder-dot.balance #7c3aed`（`styles.css:658`）、`.reminder-dot.sample #0891b2`（`styles.css:661`）、`.alert.warn` 边框 `#f0dcb0`、`.btn.danger` 边框 `#e8c4c0`。
  - 统计卡颜色是**每页现挑**的：`Dashboard.tsx:51,56,67`（accent/amber/无色/green）、`OrderDetail.tsx:266,274,311`（accent/green/无色/amber）、`Reports.tsx:64,69,85`（accent/green/amber）。
- **量化依据**（运行时实测）：工作台 4 张统计卡 = **25px 蓝 / 20px 黄 / 25px 黑 / 20px 绿**，卡内高度 38px vs 30px；全屏文字色 **10 种**、tag 底色 **5 种**、待办圆点 **2 种**（`rgb(124,58,237)` 紫、`rgb(8,145,178)` 青）。紫和青在整个 CSS 变量体系里**没有任何来源**。
- **为什么是问题**：4 个颜色并排时，**没有一个是重点**。业务员扫工作台第一眼该看到"待收款金额"，但它和另外 3 个卡在争注意力。紫/青圆点更是纯噪音——看到紫色不知道意味着什么。
- **改法**：
  1. 删掉 `.reminder-dot.balance` 的 `#7c3aed` 和 `.reminder-dot.sample` 的 `#0891b2`（`styles.css:658,661`），5 个圆点全部改用 `--accent / --warning / --danger` 三色。
  2. 统计卡上色规则写进规范：**同屏最多 2 张卡上色**，其余用 `--text` 中性。卡片颜色 = 语义，不是"给这张卡找个颜色"：进行中/主指标 → `--accent`；已完成/正向金额 → `--success`；需关注/待收 → `--warning`；异常 → `--danger`。
  3. 4 张卡的数字字号**必须一致**（`design-system.md` §5.5）。
  4. 颜色值本身也要改：`--success #12855f`→`#0f6b4c`、`--warning #b26a00`→`#8a5200`、`--danger #c0392b`→`#a53024`（见 S6）。

### S3. 状态控件形态不统一：同一状态有标签和下拉两种长相

- **现象**：
  - 订单列表：`PaymentTag` / `ShipTag` 彩色标签（`Orders.tsx:170-176`，`ui.tsx:145-166`）。
  - 报价列表：**两个下拉框**（`Quotations.tsx:171` 状态、`Quotations.tsx:185` 结果）。
  - 打样单列表：**下拉框**（`Samples.tsx:208` 状态）+ 一个标签（`Samples.tsx:225` 打样费收款）。
  - 订单详情页：**顶部是标签**（`OrderDetail.tsx` 页头 已收款/备货中），**右侧"状态推进"卡片里又是下拉框**（`OrderDetail.tsx:455,472`）——**同一屏、同一个"收款状态"，两种形态**。
- **量化依据**：全系统 35 处 `<select>`，其中 4 处被放在**表格单元格内**当状态展示。报价页行高 **50px**（下拉 33px 撑起来的），而订单页行高 38px、报表 36px——**同样是列表，行高差 14~14px**。打样单的状态下拉实测宽 **24px**（只剩一个箭头），报价的状态下拉宽 **157px**。
- **为什么是问题**：24px 宽的下拉框根本读不出当前状态；50px 和 36px 的行高差会让上下扫视时串行；同屏两种形态会让人怀疑"这两个状态是不是不一样的东西"。
- **改法**：
  1. **列表一律用只读 tag**，要改状态进详情页/编辑弹窗改。改 `Quotations.tsx:171,185`、`Samples.tsx:208`：状态/结果列改成 `.tag`（报价/打样状态需补 `design-system.md` §3.4 映射表里的对应语义色 + `QUOTATION_STATUS_LABEL` / `SAMPLE_STATUS_LABEL`）。
  2. **订单详情页**：顶部状态改用与"状态推进"卡片**同一套**控件（建议两处都用只读 tag + "修改"入口进弹窗），消除同屏双形态。
  3. 补 `.select.sm` 样式（现在这个类**根本不存在**，`styles.css` 里只有 `.btn.sm`，`select.sm` 完全无效）：

     ```css
     select.sm {
       height: 22px; padding: 0 4px; font-size: var(--text-sm);
       width: auto; min-width: 64px; border-radius: var(--radius-md);
     }
     ```
     报价/打样列表里仍要保留可编辑的话，至少高度收到 22px（= `.btn.sm` 高度），行高回到 36px。
  4. `Samples.tsx:142` 的"全部状态"筛选下拉现在 **1168px 满宽**（实测），改成 `style={{ width: 160 }}`，和 `Orders.tsx:72` 的排序下拉一致。

### S4. 间距没有刻度，24 个不同数值

- **现象**：`styles.css` 的 `padding` 出现 2/3/4/5/6/7/8/9/10/12/13/14/15/16/17/18/20/22/24/44px（统计见 §1 映射表）；`.card` margin-bottom 18px、`.content` padding 20px 24px、`.card-body` 16px、`.card-head` 12px 16px、`.stat` 15px 17px、`.modal-body` 18px、`.modal-head` 14px 18px、`.modal-foot` 12px 18px、`.toolbar` gap 9px、`.tabs` padding `0 16px`、`.tab` padding 10px 13px、`.field` margin-bottom 12px、`.field-row` gap 0 14px。
- **量化依据**：仅 `.card` 体系内部就有 **4 种内边距**（15×17 / 12×16 / 16 / 0）；`.stat` 的 15px/17px 是**奇数**，在 125% 缩放下等于 18.75/21.25px，直接错位。弹窗体系内部有 3 种（14×18 / 18 / 12×18）。
- **为什么是问题**：17px 和 16px 的差 1px，业务员不会"看出"哪里不齐，但**眼睛能感觉到**——两张卡片并排时边框对不齐，就是那种"说不上来哪里怪"。
- **改法**：`design-system.md` §1 的 spacing scale（4/8/12/16/20/24/32）+ 逐值映射表。奇数值（15/17/13/9/7/5）全部收进刻度。

### S5. 表格列数失控，长文本撑爆行高，1366px 笔记本上必然横向滚动

- **现象**（运行时实测）：

  | 页面 | 列数 | 表格最小宽 | 容器宽 | 结果 |
  |---|---|---|---|---|
  | 订单 `Orders.tsx:112` | **13** | 1284px | 1166px | **溢出 118px，出现横向滚动条** |
  | 打样单 `Samples.tsx:167` | **14** | 1269px | 1166px | 溢出 103px + 行高 76/92px |
  | 报价 `Quotations.tsx:147` | 7 | — | — | 行高 50px（下拉撑的） |
  | 商品库 `Products.tsx:199` | 8 | — | — | 行高正常 |
  | 客户 `Customers.tsx:136` | 7 | — | — | 行高正常 |

  - 打样单"客户"列宽 68px，`Acme Fashion GmbH` 被迫折成 3 行（`out/shots/samples.png`），行高 76/92px；"款号"列 58px，`TS-001、PL-002` 也折行。
  - 订单列表"含费用合计"格里塞了主值 + 10px 的"含运费保险"副注（`Orders.tsx:139-147`），把该行从 38px 撑到 ~52px。
  - 商品库"成本价"表头左对齐、数值右对齐（`Products.tsx:199` 的 th 无 `.num`），客户库"地址"列用 `--text-faint` 而其余列是深色（`Customers.tsx:155` `<td className="muted faint">`），强调规则不统一。
- **量化依据**：工作台"最近订单"表行高 38px，报价 50px，打样单 76/92px——**四个列表页面行高差 54px**。13/14 列的表在 1366px 笔记本上（主区 1158px - 内容内边距 48px = 1110px）溢出 174px。
- **为什么是问题**：业务员的工作是"横向扫一列找那一行"，行高不齐 + 横向滚动条 = 视线要不断回卷。订单列表 13 列意味着每行有 13 个视觉锚点，一天扫 200 行 = 2600 次锚点切换。
- **改法**：
  1. **列表表格硬上限 12 列**，本轮先把订单表 13 → 11：合并 `PI号`（降级到 hover/详情）、`含费用合计` 与 `货值` 合并成"货值 / 含费用"、`预计出货` 与 `创建日期` 合并成"时间"。
  2. 打样单表 14 → 11：去掉双行表头（`样品费<br/>应收客户` 这种，`Samples.tsx:172-179`），副说明改 `title`。
  3. 客户名列设 `max-width: 220px` + `text-overflow: ellipsis`（新类 `.cell-clip`），款号列同理，避免长文本折 3 行。
  4. "含运费保险"副注改 `title` 提示，不要撑行高。
  5. **数字列表头必须加 `.num`**：商品库"成本价"、工作台"金额"（`Dashboard.tsx` 表头 `金额` 左对齐、数据右对齐）都要改。

### S6. 文字对比度不达标：辅助文字只有 2.58:1

- **现象**：`--text-faint: #98a2b3` 用在：表格日期列（订单"预计出货""创建日期"、商品库/客户库无）、`.hint`、`.stat-hint`、"共 N 单"、"PI号"列、客户库"地址"列。
- **量化依据**（WCAG 对比度计算）：

  | 组合 | 现状 | 结论 | 建议值 | 改后 |
  |---|---|---|---|---|
  | `#98a2b3` on `#ffffff` | **2.58:1** | 不合格 | `#5c6878` | 5.67:1 |
  | `#98a2b3` on `#f4f6f9` | **2.38:1** | 不合格 | `#5c6878` | 5.23:1 |
  | `#b26a00` on `#fdf2dd`（tag amber） | **3.82:1** | 不合格 | `#8a5200` | 5.76:1 |
  | `#12855f` on `#e4f5ee`（tag green） | **4.09:1** | 不合格 | `#0f6b4c` | 5.76:1 |
  | `#c0392b` on `#fdeceb`（tag red） | 4.76:1 | 勉强 | `#a53024` | 6.03:1 |
  | `#6f7c94` on `#131a2a`（侧栏版本号） | **4.12:1** | 不合格 | `#8b97ad` | 5.90:1 |
  | `#667085` on `#ffffff`（text-dim） | 4.97:1 | 合格 | 不变 | — |
  | `#2f6fed` on `#eaf1fe`（accent-soft 上用 accent） | 4.01:1 | 不合格 | `#2158c9` | 5.60:1 |

- **为什么是问题**：2.58:1 的灰色在笔记本低亮度屏上基本等于"看不清"，而这恰恰是**订单创建日期、预计出货日**这些业务员天天要扫的列。
- **改法**：`--text-faint` 改 `#5c6878`（同时它比 `--text-dim #667085` 深一点，正好拉开两级）；tag 的 warning/success/danger 文字色按上表改；侧边栏次要文字用新变量 `--sidebar-text-dim: #8b97ad`。**改色值时 `styles.css` 里的 `.tag.amber/.tag.green/.tag.red` 文字色要跟着一起改**，否则底色改了字没改。

### S7. 圆角和阴影各写各的，同类元素长得不一样

- **现象**：圆角出现 **4px**（`.chip`）、**6px**（`.btn`/input/select/`.tag` 的兄弟类/`.picker-list`/`.img-thumb`）、**8px**（`.card` 的 `--radius`）、**9px**（`.nav-badge`）、**10px**（`.modal` + `.modal-foot` 又单独写了一遍 `border-radius: 0 0 10px 10px`）、**11px**（`.tag`）、**50%**（`.reminder-dot`/`.timeline-dot`）。阴影有 4 套：`--shadow`、`.doc-page` 的 `0 3px 16px rgba(0,0,0,.3)`、`.img-thumb.primary` 的 `0 0 0 2px`、input focus 的 `0 0 0 3px`。
- **量化依据**：`.tag` 圆角 11px 配 18px 行高 = 胶囊；`.nav-badge` 圆角 9px 配 17px 行高 = 也是胶囊但数值不同；`.chip` 圆角 4px 配 12px 字号 = 方角。**同一个"小圆角标签"概念有 3 种长相**（tag 11px / chip 4px / badge 9px）。
- **为什么是问题**：这类差异单独看都不刺眼，**放一起才刺眼**——业务员从"待确认"标签看到"尺码 M"标签再到"2 项"角标，会觉得"这仨不是一家的"。
- **改法**：`design-system.md` §4 的圆角/阴影 token。`.tag` 与 `.nav-badge` 统一 `--radius-pill`（999px），`.chip` 用 `--radius-sm`（4px），`.modal` 与 `.modal-foot` 共用 `--radius-xl`（10px）。

## 三、单页问题

### P1. 工作台 `/`：4 张统计卡 4 个颜色、两种字号

- **现象**：`Dashboard.tsx:51-75`，4 张 `.stat` 依次是 accent(蓝)/amber(黄)/无色(黑)/green(绿)。
- **量化依据**（实测）：数字字号 **25px / 20px / 25px / 20px**，卡内数字高 38px vs 30px，颜色 `rgb(47,111,237)` / `rgb(178,106,0)` / `rgb(28,35,51)` / `rgb(18,133,95)`。工作台整屏另有 5 种 tag 底色 + 2 个紫/青圆点 + 表格里 6 个状态标签，**一屏 8 个以上彩色元素**。
- **为什么是问题**："待收款金额"是这张卡里唯一要行动的信息，却和另外三张平等争抢。
- **改法**：4 张卡字号统一 `--text-display`（24px）；只给"待收款金额"上 `--warning`、"待出货订单"上 `--accent`，另两张用 `--text` 中性。

### P2. 工作台"最近订单"表：金额格把金额和数量塞在一起

- **现象**：`Dashboard.tsx:181` 金额列渲染成 `{money(o.grandTotal ?? o.totalAmount, o.currency)} / {num(o.totalQuantity)} 件`；且该列表头 `Dashboard.tsx:165` 是裸 `<th>金额</th>`（无 `.num`），数据格 `Dashboard.tsx:178` 是 `className="num"`（右对齐）——**表头左、数据右**。
- **量化依据**：同屏统计卡用 `CNY 63,813.75` 格式，表格用 `USD 7,575.00 / 900 件`，**同一屏两种货币写法**；且这格同时承担"金额"和"件数"两个语义。
- **为什么是问题**：`USD 0.00` 是"这单还没录货值"还是"真的是 0"，业务员分不清；`/ 3 件` 用斜杠分隔两个不同量纲的数字，眼睛要在中间做一次语义切换。
- **改法**（只动呈现，不动业务）：金额格只放 `USD 0.00`（缺数据按 `design-system.md` §5.10 统一显示 `—`），件数单独一列或跟在括号里 `USD 0.00（3 件）`。

### P3. 订单详情页 `/orders/133`：顶部操作区 4 种按钮形态

- **现象**：`OrderDetail.tsx:236-250` 页头右侧依次是 `商业发票 CI`（描边按钮）、`生成 PI`（主按钮）、`作废此单`（纯文字）、`删除订单`（红色纯文字）。
- **量化依据**：同屏 `.btn` 只有描边/主 2 种，文字链接却有普通和红色 2 种，共 **4 种形态**；`.btn.danger`（`styles.css:204`）明明定义了却没被用在这里。
- **为什么是问题**：4 个按钮并排，**用户不知道哪个是主操作**。而且"作废"和"删除"是两种危险操作，却一个是无样式文字、一个是红字，危险等级没有被视觉区分。
- **改法**：改成 **描边按钮 `作废此单` + 主按钮 `生成 PI`**，把 `商业发票 CI` 和 `删除订单` 收进"更多"下拉（或者：`生成 PI` 主按钮 + `商业发票 CI` 描边 + `⋯` 溢出菜单装作废/删除）。删除/作废统一用 `.btn.ghost.danger` 或菜单里的红色项。

### P4. 订单详情页"客户与条款"：标签列不对齐

- **现象**：该卡片用**带虚线引导点的文本行**排布（`OrderDetail.tsx` 客户与条款区），标签左边缘随标签长度浮动：`客户` 在 x=262、`交期` 在 x=320、`运费（运费/保险）` 在 x=262 且长 98px，值一律右对齐到 x=762。
- **量化依据**：同卡片内 15 个字段行的标签起点在 **3 个不同位置**（262 / 320 / 393），值列右边缘却在同一个位置——说明值列对齐了、标签列没对齐，形成"参差"的锯齿边。
- **为什么是问题**：这块是业务员建单后核对条款最频繁的地方，锯齿状的左边缘让"扫一列标签"完全做不到。
- **改法**：改成 2 列表格（或 `display:grid; grid-template-columns: 120px 1fr`），标签左对齐固定 120px 列宽，值左对齐（不要右对齐——长文本左对齐才好扫）。**只改排版，不动字段内容。**

### P5. 报价列表 `/quotations`：状态/结果用下拉框，宽度失控

- **现象**：`Quotations.tsx:171,185` 两个 `<select className="sm">`。
- **量化依据**：`.sm` 类对 select **完全无效**（`styles.css` 只有 `.btn.sm`），于是继承全局 `width:100%` + `padding:6px 9px` + 13px 字号 → 实测下拉 **157px × 33px** 和 **121px × 33px**，行高被撑到 **50px**（其它列表 36~38px）。而"结果"这一列整列 121px 宽只为放两个字。
- **为什么是问题**：一个只读状态的展示位用了可编辑控件的形态 + 33px 高度，直接把行高抬高 33%；而且两个下拉挤在表里，误点就改状态。
- **改法**：同 S3——列表里状态/结果改只读 tag；此处 select 若必须保留，套上面给的 `select.sm` 规则（22px 高）。

### P6. 打样单 `/samples`：14 列 + 客户名折 3 行 + 筛选下拉满宽

- **现象**：`Samples.tsx:167` 表头 14 个 `<th>`；`Samples.tsx:142` 状态筛选 `<select>` 没有宽度约束。
- **量化依据**（实测）：表格最小宽 1269px / 容器 1166px（溢出 103px）；行高 **76px 和 92px**（标准 36px）；"客户"列 68px 宽，`Acme Fashion GmbH` 折 3 行；"款号"列 58px，`TS-001、PL-002` 折行；筛选下拉 **1168px 满宽**（订单页同类下拉是 160px）；表头"状态"列下拉只有 **24px 宽**。
- **为什么是问题**：一张表占 92px 行高 = 一屏只能看 9 行；客户名折行导致"同一家客户"在视觉上对不齐；满宽下拉点一下弹出一列 15 个选项还要滚动。
- **改法**：筛选下拉 `width:160`；状态下拉换 tag（同 S3）；客户列 `max-width:200px` + 省略号 + `title`；表头去掉双行（`样品费<br/>应收客户` 改 `title`）；列数 14 → 11。

### P7. 报表 `/reports`：用黄色警告条承载操作说明

- **现象**：`Reports.tsx` 页面上方一条 `.alert.warn`（琥珀底）里写的是"有成本记录不全的单：2026-10（1 单）…补录入口：到「订单」里打开那一单 →「商品明细」表 → 成本那一栏直接填数字"。这是**操作指引**，不是警告。
- **量化依据**：`.alert.warn` 底 `#fdf2dd`、字 `#b26a00`（对比度 3.82:1，偏低）；而它描述的内容是"需要你去做一件事"，语义上属于"注意"不是"出错"。同时报表页 4 张统计卡也是 4 个颜色（accent/green/无色/amber）。
- **为什么是问题**：把说明做成黄色警示条，业务员会以为系统出错了；琥珀色字本身也偏淡。
- **改法**：改用 `.alert.info`（`--accent-soft` 底 + `--accent-hover` 字）；如果确实要"有 1 单成本不全"的强调，把这 1 单做成一个可点的行/按钮，而不是塞在说明条里。

### P8. 打印单据（pi/pl/quotation）：表头与数据列不对齐 + 中英数字挤在一格

- **现象**：`styles.css` 的 `.doc-page th` 没有 `.num` 规则（只有 `td.num` 右对齐），三张单据的 `Amount / 金额` 表头左对齐、数据右对齐。
- **量化依据**（`out/shots/doc-pi.png` 实测）：`Amount / 金额` 表头文字起始 x=490，数值 `1875.00` 结束 x=546，**表头和数字不在同一条竖线**；`Sub-total / 小计` 列的单元格内容是字符串 `小计 1875.00`（中文 + 数字拼在一起，不参与数字右对齐，PI/PL/报价单三张单据都有这个问题）；PI 合计行的 `900` 落在 `Amount` 列下方而不是 `Qty` 列下方。
- **为什么是问题**：PI 是要发给海外客户的正式单据，**对不齐的表头在客户眼里就是"这单不专业"**，直接影响信任。
- **改法**（只动 CSS/模板，不动金额计算）：
  1. 加 `.doc-page th.num { text-align: right; }`，并给 Amount/小计 的 `th` 加 `class="num"`。
  2. 小计单元格只放数字 `1875.00`，"小计"二字移到表头。
  3. 合计行的 `colSpan` 与上方列数对齐（PI 合计行 `900` 应落在 Qty 列）。

### P9. 设置页 `/settings`：表单控件全部满宽，短值也拉满

- **现象**：`Settings.tsx` 中"电话""邮箱""网站"三个短字段各占一整列（`grid-2` 的一半 ≈ 570px），`公司名称` 独占 1100px。
- **量化依据**：`grid-2` 间距 16px、`field-row` 间距 14px（两个不同的栅格间距值）；标签 12px、值 13px，`.field` 间距 12px。整页没有一处宽度约束，与订单详情里"同一字段在 3 个不同宽度"的情况叠加后，用户没有肌肉记忆。
- **为什么是问题**：这是填一次、存很久的页面，浪费的不是空间而是"我不知道该填多长"的暗示。
- **改法**：给输入框加语义宽度类（`.w-full` / `.w-md` 320px / `.w-sm` 160px），公司名/地址满宽、电话/邮箱半宽、网站 220px；栅格间距统一 `--space-4`（16px）。
