# R101 研发报告 —— 审计路由匹配收口（参数路由单段、负向探针显式豁免）

日期：2026-11-15。基线 v0.5.43。每条标「已做并验过 / 已做但没验 / 没做（原因）」。
本轮有代码改动（审计脚本、匹配器自测、e2e 负向探针），但**无渲染层改动**：
无 UI 形态，无截图义务，证据为审计输出与断言结果。

## 一、做了什么

1. **共享路由匹配器**（已做并验过）：`scripts/lib/audit-shared.cjs` 新增
   `normalizePath()`、`matchRoute()`、`findServerRoute()`。归一规则为截掉 `?` / `#`、
   补前导斜杠、去非根尾斜杠、空串归 `/`；`:param` 只吃一个非空路径段，段数必须严格相等；
   查找时精确路由优先于参数路由，字符串与对象两种路由表都支持。
2. **B2 参数化误报收口**（已做并验过）：`scripts/audit-ipc-wiring.cjs` 的硬闸 B2
   从 `serverRoutes.includes()` 改为 `findServerRoute()`。此前 `/api/files/images/:name`
   这类参数路由会被误判为「server 控制器里不存在」，现在单段实际路径能正确命中；
   多一段、空参数仍报红，参数路由没有被放宽成前缀通配。
3. **HTTP 反向对表收口**（已做并验过）：`scripts/audit-http-coverage.cjs` 反查控制器时
   改用共享 `matchRoute()`；移除裸 `/api/no-such-route` 按名豁免，改为只豁免带显式标记的
   精确字面量 `/api/no-such-route?audit=negative-probe`。新增「过期豁免」检查：声明了探针
   但 e2e 正文里没出现也报红。
4. **e2e 探针加标记**（已做并验过）：`server/test/e2e.ts` 的未知路由探针改为
   `POST /api/no-such-route?audit=negative-probe`，仍断言 404 与中文错误体
   「没有这个接口」。
5. **匹配器自测**（已做并验过）：新增 `scripts/audit-route-match-test.cjs`，18 项覆盖
   精确匹配、单段参数、多段拒绝、空参数拒绝、尾斜杠/query/hash 归一、根路径、精确优先、
   字符串/对象路由表。`package.json` 新增 `audit:route-match` 并串入 `test:all`；
   `README.md` 测试清单同步。
