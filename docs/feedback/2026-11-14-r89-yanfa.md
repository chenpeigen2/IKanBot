日期：2026-11-14。基线 v0.5.30。每条标「已做并验过 / 已做但没验 / 没做（原因）」。

## 一、做了什么

1. **工作台开屏自检**（已做并验过）：Dashboard 的 load()（与既有 60 秒刷新/窗口聚焦同拍）
   顺带调一次 `window.api.settings.health()`——本机读本机、远端读服务器（谁的数据显示谁的
   健康，通道语义 R83 已锁）。`ok===false` 时页面顶部挂红条：「数据自检没通过——请先不要
   录单。」+ problems 首条人话 + 跳转链接「设置 · 数据备份 · 数据自检」（详情、12 表行数、
   自检原文都在那儿，消费的是同一条 problems 清单——两处 UI 一个数据来源）。
2. **故障分层**（已做并验过）：health 通道整体跑不起来（远端断、磁盘错）时 catch 静默回
   null——工作台不挂红条也不崩，那类故障有自己的提示路（远端断有「请先登录/连不上后端」
   的既有链路）；统计卡的 loadError 逻辑不受影响。
3. **红验证**（已做并验过）：stash 旧 Dashboard 实跑——三条 check 全 ✗（settings.health 调用
   与 ok===false 条件 / 红条文案与跳转 / catch 回 null），stash pop 还原后复绿（2556 全绿）。
