# 整库搬迁操作手册（老桌面 → 服务器）

> 适用于：把一台电脑上的 IKanBot 全部数据（订单、客户、商品、打样、报价、图片、单据存档）
> 搬到另一台电脑或自建服务器。全程约 10 分钟，分四步，每步都有核对点。

## 前提

- 新机器已装好 IKanBot（安装包在 GitHub Releases 下载）或服务器已部署后端
- 两边都能访问 GitHub Releases（升级用），版本**两边一致或新机器更新**
- 老机器上的数据结构版本 ≤ 新机器（新程序能读老数据；反过来会被版本守卫拦下，
  提示「这份数据的新版结构是 vX，当前程序只认到 vY」——先升级老程序再导出）

## 第 1 步：老桌面导出整库

设置 → 数据备份 → **「导出整库（搬迁用）」**。

- 生成的 zip 在本机备份目录（设置页显示的「备份目录」路径），文件名带 `-export`
- 包里含：数据库、商品图片、单据存档 PDF、**导出那一刻的搬迁对账**（12 张核心表行数、
  收款合计、单号唯一性、客户预收余额——恢复后自动逐项核对）
- 核对点：toast 显示的导出路径存在、文件大小不为 0

## 第 2 步：把包带到新机器/服务器

- 手动方式：拷贝 zip（U 盘/网盘均可），放到新机器的备份目录
- 远端方式：新机器的桌面在远端模式下「从备份恢复…」选这个本机 zip——
  桌面会自动把它上传到服务器备份目录（v0.5.12 起），不需要手动放

## 第 3 步：新机器恢复

设置 → 数据备份 → 备份列表里选这份包（或「从备份恢复…」选本机 zip）→ 看摘要 → 确认替换。

- 恢复前程序会自动把新机器当前数据先备一份（pre-restore，选错还能退回来）
- 恢复期间后端会挡住别人的录单请求（「恢复期间请全员停手」），桌面本机模式则程序重启一次

## 第 4 步：对账核对

恢复完成后设置页亮出**「最近一次恢复的搬迁对账」**：

- 绿行「与包内对账逐项对平」= 恢复后的库与导出那一刻逐项一致（表行数、收款合计、
  单号唯一性、客户预收余额全零差）——可以开始用了
- 红块「对账不平」= 包或恢复有一头出了问题，**别用这份数据录单**，按差异明细来问
- 显示「这份包没有带对账」= 包是 v0.5.12 之前导出的，升级后重新导出一份再恢复

## 回滚

- 恢复前自动打的 pre-restore 包就是反悔药：再恢复一次那份即可回到恢复前的样子
- 服务器侧：备份列表里 pre-restore 包同样可见可恢复
